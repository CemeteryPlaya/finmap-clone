## 1. Цель, решения владельца, границы

**Цель.** Модуль сам забирает отчёты Senet по кассовым сменам клуба и после закрытия смены записывает её в журнал так, как владелец годами делал это вручную в Finmap:
- доходы смены: «Каспи» и «Касса»;
- выемки из кассы: расходы по правилам.

Что правила не распознали, попадает в очередь «Разобрать». Экран «Сверка Senet» остаётся контролем: на нём видно, совпадает ли остаток кассы в журнале с остатком Senet после каждой смены.

**Почему сейчас.** Application Key от ENESTECH пока не выдан. Отчёты админ-панели дают те же данные, и алгоритм уже проверен на настоящем октябре:
- за 1–7.10 совпала 61 операция из 62, с ручной разноской владельца;
- по 48 сменам 08–31.10 остаток кассы совпал после каждой смены.

Когда ключ придёт, меняется только источник данных (§3).

### 1.1 Решения владельца

**2026-11-02, бриф задачи:**

| № | Решение |
|---|---|

| 2 | Временный источник — внутренний API админ-панели с токеном пользователя Senet. Источник спрятан за интерфейсом `SenetSource`: реализация `AdminTokenSource` делается сейчас, `AppKeySource` — когда выдадут ключ |

### 1.2 Границы

**Входит:**
- подключение, вход в Senet и хранение секретов;
- забор отчётов, сырые xlsx, журнал забора;
- автопроводка смен;
- правила разноски, очередь «Разобрать», «Проверить на истории»;
- «Сверка Senet» с колонкой «Касса после смены»;
- сбор данных для склада и аналитики (§9.3);
- запуск по расписанию на Vercel и локально;
- сверка с эталоном — только на машине владельца.

**Не входит:**
- Telegram-бот и вопросы по платежам Kaspi — отдельная спецификация. Очередь (§6) подключает его без переделки;
- «Склад-Senet» — документы склада не создаются;
- вкладки «Аналитики клуба»;
- доходы Senet Pay (решение 7);
- запись чего-либо в Senet. Только чтение — за одним исключением: запрос входа (§3.2);
- автоматическая корректировка уже проведённой выручки (§5.4).

**Антицели** — что считается провалом, даже если «работает»:
- повторный забор создал дубль;
- модуль незаметно изменил проведённую операцию;
- в журнал попал контрагент-владелец, которого владелец не заводил;
- пароль, токен или телефон гостя виден в браузере, в истории или в логах;
- настоящее имя или сумма клуба попали в репозиторий.

## 3. Источник данных

### 3.1 Интерфейс `SenetSource`

Остальной модуль знает только этот интерфейс:

```ts
interface SenetSource {
  /** Проверка доступа: смены кассы за последние сутки. */
  check(office: OfficeRef): Promise<CheckResult>;
  /** Отчёт за окно [from, to) в UTC: разобранные строки и сырой файл. */
  report<K extends ReportKind>(kind: K, office: OfficeRef, from: Date, to: Date): Promise<{ rows: ReportRows[K]; raw: RawFile }>;
}
type ReportKind = 'sessions' | 'cashMoves' | 'transactions' | 'soldItems' | 'checks' | 'refills' | 'stock' | 'goodsMoves' | 'load';
```

- **Строки** — типизированные записи с временем в UTC и деньгами в тиынах. Разбор xlsx (сейчас) и json (с ключом) — забота реализации.
- **`AdminTokenSource`** — делается сейчас (§3.2–§3.4).
- **`AppKeySource`** — по §2 спецификации 2026-10-15, когда придёт ключ. До тех пор подключение с `source = app_key` создать нельзя.
- **Ключ смены.** В отчёте админ-панели нет номера сессии. Если он найдётся в json `AppKeySource`, ключ смены не меняется, а номер сохраняется рядом.

### 3.2 Вход и токен (зафиксировано 2026-11-02)

**Вход:**
- `POST https://{org}.app.enes.tech/api/v2/user/idm_admin_auth/`, тело `{"username": …, "password": …}`;
- ответ: `{"token": …, "keycloak_refresh_token"?: …}`;
- токен — JWT без поля `exp`. Он живёт до выхода из сессии или смены пароля.

**Запросы отчётов** — с заголовком `Authorization: Token {token}`.

**Способы подключения:**
- **«Логин и пароль Senet»** — рекомендуемый. Владелец заводит в Senet отдельного пользователя только для отчётов. Сервер сам входит и получает токен:
  - при первом заборе;
  - при ответе 401 — один раз; новый токен сохраняется.
- **«Токен»** — запасной. Нужен, если вход запросит код подтверждения (у админ-панели есть такой путь для части учёток) или пойдёт через SSO (Keycloak). Токен вставляется вручную; подсказка у поля объясняет, как скопировать его из админ-панели.

**При отказе** — 401 после повторного входа, неверный пароль или ответ, требующий подтверждения:
- подключение получает статус `key_rejected`;
- над журналом и «Сверкой Senet» появляется баннер «Обновите доступ к Senet»;
- почасовой забор этого подключения останавливается до замены данных входа.

**Без выхода.** Модуль никогда не вызывает выход (`/api/v2/user/disconnect/`): он снял бы токен и у админ-панели.

### 3.3 Запрос отчёта

`GET https://{org}.app.enes.tech/api/v2/stat/reports/?format=xlsx&office_id={id}&type={тип}&from_date={UTC}&to_date={UTC}[&cash_desk_id={касса}]`

- **Даты:** `from_date` и `to_date` — ISO в UTC с `Z` и миллисекундами.
- **Время внутри xlsx** — без пояса, в часах клуба. Перевод — явный, по `APP_TIMEZONE` (по умолчанию `Asia/Almaty`, UTC+5), а не по часам сервера.
- **Формат — только xlsx.** `format=json` сервер игнорирует, а у части отчётов отвечает 500.
- **Разбор:**
  - читалка — `imports/xlsx-read.ts`;
  - колонки ищутся по заголовку первой строки, а не по позиции;
  - нет обязательной колонки → отчёт «в незнакомом формате» (§11): сырой файл сохраняется, запуск получает `partial`.
- **Пределы** — §5.5 спецификации 2026-10-15: таймаут 60 с, ответ до 20 МБ, пауза 200 мс между запросами, один повтор при сетевой ошибке или 5xx.

### 3.4 Отчёты

| `ReportKind` | `type` | Ключевые колонки | Зачем |
|---|---|---|---|
| `sessions` | `cashdesk_session` (+ `cash_desk_id`) | Время начала сеанса, Время конца сеанса, Пользователь открывший / закрывший, Сумма, Наличный / Безналичный расчёт | Смены. «Сумма» — **остаток в кассе на закрытии**, не выручка. Пустой конец — смена открыта, пропускается |

## 4. Алгоритм разноски

**Эталон.** Алгоритм повторяет `senet_to_finmap.py`. Эталон лежит только у владельца, в `.superpowers/senet-local/` (каталог в `.gitignore`). Если описание брифа расходится с эталоном, побеждает эталон: приёмка требует ноль расхождений. Такие места помечены **«как в эталоне»**.

**Где живёт.** Расчёт — чистые функции без базы в `src/server/modules/senet/posting/`. Им передаются смены, выемки, правила и настройки клуба, а возвращают они план операций. Запись плана в журнал — §5.

### 4.1 Смена и её выручка

- **Порядок.** Закрытые смены одной кассы клуба сортируются по началу.
- **Окно смены** — `(конец предыдущей смены, конец этой смены]`:
  - выемки делают до закрытия, иногда раньше начала следующей смены — поэтому окно привязано к концу;
  - предыдущая смена берётся из базы, а не только из текущего ответа;
  - у самой первой известной смены окно начинается за 10 секунд до её начала.
- **Внесения** окна — остаток прошлой смены. Это не доход.
  - Контроль: сумма внесений = «Сумма» прошлой смены.
  - Расхождение — предупреждение в сверке, не ошибка.
- **Выручка смены** = `остаток на закрытии − Σ внесений окна + Σ выемок окна`.
  - Контроль: выручка = Σ `transactions` за `[начало, конец]`, покупки минус возвраты.
  - Расхождение — предупреждение «Выручка не сходится с транзакциями Senet на N ₸».
- **Безнал.** Senet учитывает безнал как наличные (решение владельца брифа): всё идёт на счёт кассы. Kaspi выделяется только из выемок (§4.2).

### 4.2 Доходы смены

- **Каспи** = сумма выемок типа «Каспи» (§4.3, тип 2).
  - Это не расход: так кассиры отмечают оплаты через Kaspi POS.
  - Проводится доходом в категорию дохода смены клуба на счёт Kaspi клуба.
  - Выемки «Каспи» в смене нет → доход Каспи не создаётся, а в очередь идёт пункт «Нет выноса kaspi» (§6.2).
- **Касса** = выручка − Каспи.
  - Доход в ту же категорию на счёт кассы клуба.
  - Отрицательная сумма → доходы смены не проводятся, смена идёт в очередь (§6.2). Выемки при этом проводятся как обычно.
- **Нулевые суммы** не проводятся.

### 4.3 Классификация выемки

**Нормализация комментария:**
- нижний регистр, `ё → е`;
- всё, кроме букв, цифр и `_`, — пробел;
- пробелы схлопнуты, края обрезаны.

Латиница не переводится: кассиры пишут транслитом (`zp …`, `obed`).

**Виды совпадения слова или фразы** — их выбирают при правке правила:
- «слово» — нормализованное слово целиком;
- «фраза целиком» — весь комментарий;
- «начинается с»;
- «содержит» — подстрока.

**Типы правил — по порядку**, срабатывает первое (порядок как в эталоне):

| № | Тип | Условие | Результат |
|---|---|---|---|
| 1 | **Точное** | Нормализованный комментарий = шаблон правила. Создаётся из очереди (§6.3) или вручную | Категория, контрагент и комментарий правила |
| 2 | **Каспи** | Комментарий целиком — слово из списка «Каспи» | В доход Каспи (§4.2) |
| 3 | **Стажёр** | Есть слово стажёра, и (есть признак ЗП или в комментарии ≤ 3 слов) | «Зарплата» без контрагента, комментарий «стажер» |
| 4 | **Зарплата** | Первое слово или любое слово — из списка признаков ЗП | См. ниже |
| 5 | **Мастер** | Есть алиас мастера | Категория правила (у владельца — «Строительство и ремонт»), контрагент — мастер |
| 6 | **Дивиденды** | Есть слово из списка «Владельцы и семья» | См. ниже |
| 7 | **Только имя** | Комментарий — одно слово, и это алиас сотрудника | В очередь с подсказкой «Зарплата, {сотрудник}» |
| 8 | **Обед** | Слова или фразы обеда | Категория обеда (у владельца — «Обед») |
| 9 | **Ключевые слова** | Список «вид совпадения + слова → категория, контрагент, комментарий». Порядок задаёт владелец | Категория правила. Комментарий — текст или «исходный текст» |
| 10 | **Бар** | Шаблон `<товар><кол-во>x<цена>` (`\d+\s*x\s*\d+`) или слово из списка товаров бара (подстрока) | См. ниже |
| 11 | **Иначе** | — | В очередь «Разобрать» |

**Зарплата (тип 4):**
- **Есть алиас сотрудника** → «Зарплата», контрагент по справочнику алиасов «алиас → контрагент».
- **Ошибочный алиас** — запись справочника с пометкой «ошибочный». Алиас владельца в контексте ЗП означает конкретного сотрудника. Пример из данных: кассиры пишут ЗП с именем владельца, а это ЗП другого сотрудника. Пометка влияет только на подсказки и показ в правилах. Сопоставление работает как у обычного алиаса — как в эталоне.
- **Алиаса нет, но есть слово доплаты** (`dop`, `доп`) → контрагент — первый сотрудник, получивший ЗП в этой же смене, в порядке выемок. Такого нет → в очередь.
- **Ни алиаса, ни доплаты** → в очередь с подсказкой «Зарплата».
- **Дата начисления.** ЗП начисляется за смену и выплачивается сразу: дата начисления = дата операции, без периода.

**Дивиденды (тип 6):**
- Каждое слово комментария — из списка «Владельцы и семья», и все найденные имена — алиасы **владельца А** → «Дивиденды», контрагент А.
- Иначе — другое имя из списка, несколько имён (даже вместе с А) или посторонние слова → «Дивиденды», контрагент **владелец Б**.
- Какие алиасы — «владелец А», какой контрагент — А, какой — Б, задаётся в правилах.
- **Новых владельцев-контрагентов модуль не создаёт никогда.**

**Бар (тип 10):**
- **Поставщик** — по ключевым словам товара. Владелец задаёт пары «слова → поставщик» в своём порядке плюс «поставщика по умолчанию».
- **Брак** (`брак`, `brak`) → тот же поставщик, исходный текст — в комментарий операции.
- **Разбор закупки.** Все пары `товар × кол-во × цена` выемки (`sandwich10x500hot dog10x500` → две строки) сохраняются в `senet_bar_purchases`.
  - Если Σ `кол-во × цена` ≠ сумме выемки, строки сохраняются с пометкой «не сходится с выемкой».
  - Проводка от этого не меняется: в расход идёт сумма выемки.

**Где хранятся категории и контрагенты.** Правила ссылаются на категории и контрагентов компании по id: имена в коде отсутствуют.
- Удалённая или архивная категория (контрагент) в правиле → правило не срабатывает, выемка идёт в очередь с причиной «Правило ссылается на архивную категорию».
- Правила принадлежат компании. У правила может быть ограничение «только для клуба X» (решение 6: у клубов разные сотрудники).

### 4.4 Время операций — как в эталоне

`X` — время закрытия смены, с точностью до секунды (миллисекунды отбрасываются).

1. Выемки сортируются по группам: «Зарплата» (типы 3, 4) → «Обед» → «Бар» → прочие. Внутри группы — по времени выемки.
2. Первая группа встаёт в `X`, даже если зарплат нет. Каждая следующая группа «Зарплата / Обед / Бар» — на минуту позже предыдущей. Все операции одной из этих групп — в одну минуту.
3. Каждая прочая выемка — ещё на минуту позже, своя минута на каждую.
4. Доходы Каспи и Касса — последними: последняя минута расходов `+ 1`. Если расходов нет — `X + 1 мин`.

Выемки в очереди место в раскладке не занимают. Операция по ответу из очереди получает своё время по этим же правилам: после прочих выемок смены, но до доходов. Если минуты заняты, доходы не двигаются: операция встаёт в ту же минуту, что и последняя прочая выемка.

### 4.5 Остальные поля операции

- **Проект** — проект клуба. Статус `actual`.
- **Комментарий** — по правилу. Исходный текст Senet хранится в `senet_cash_moves.comment` и виден в раскрытой смене.
- **Автор** — пользователь, создавший подключение (`senet_connections.created_by`). В истории у операции пометка «через Senet».

## 5. Проводка в журнал

### 5.1 Когда

После каждого забора — для каждой **закрытой** смены клуба, у которой `opened_at ≥ «Загружать с даты»`. Смены раньше этой даты только хранятся и показываются в сверке: они уже в журнале (решение 8).

### 5.2 Как

**Одна транзакция на смену:**
- план (§4) → операции через `operations.create`;
- записи в `senet_postings` и `senet_cash_moves.operation_id`;
- пункты очереди;
- история.

Сбой одной смены не останавливает остальные: смена получает отметку ошибки, запуск — `partial`.

**Ключи:**
- смена — `(клуб, касса, начало смены)`;
- выемка — `(смена, время с миллисекундами, сумма, нормализованный комментарий)`. Если в окне две одинаковые выемки, к ключу добавляется номер повтора `1, 2…`.
- `senet_postings` — `(shift_id, kind)`, где `kind` = `kaspi | cash`.

**Повторный забор дублей не создаёт.** Проводится только то, у чего ещё нет операции, и что не отмечено «Не проводить повторно».

### 5.3 Удаление операции и «Не проводить повторно»

Операции в журнале удаляются мягко (`deleted_at`) и восстанавливаются «Отменой» в истории.

- **Удалённая операция снимает проводку.** Связь с выемкой или доходом смены освобождается. Следующий забор проведёт заново по текущим правилам — если не стоит отметка «Не проводить повторно».
- **Отметка «Не проводить повторно»:**
  - есть у выемки и у дохода смены;
  - ставится галочкой в окне удаления операции из Senet. Галочка видна только у таких операций, по умолчанию выключена;
  - снимается в раскрытой смене «Сверки».
- **Восстановление «Отменой».** Если за это время модуль провёл замену, «Отмена» удаления отказывает: «Senet уже провёл эту выемку заново — удалите новую операцию». Если замены не было, восстановленная операция снова занимает свою проводку.
- **Правка операции** (сумма, категория) проводку не снимает. Модуль её не трогает.

### 5.4 Senet изменил смену после проведения

При каждом заборе смена пересчитывается.

- **Новые выемки** (поздняя выемка, другой комментарий) проводятся по правилам.
- **Пропавшая выемка** с операцией → отметка «Выемка исчезла из Senet» в сверке. Операция остаётся.
- **Изменилась выручка** или распределение Каспи / Касса относительно проведённого → отметка «Senet изменил смену после проведения» с разницей по каждому доходу.
  - Корректировка автоматически **не** создаётся.
  - Решение за владельцем: кнопка «Перепровести доходы смены» в раскрытой смене. Она в одной транзакции меняет суммы двух доходов на новые, отметка снимается.

### 5.5 Начало истории и запуск

- **«Загружать с даты»** обязательно. Это дата и время, по умолчанию — начало первой смены, которой нет в журнале.
- Подсказка при выборе: «Смены раньше этой даты считаются уже внесёнными вручную».
- **У владельца (решение 8):** смены по 02.11 уже в журнале после теста через Claude App. В настройках клуба ставится начало первой смены после них.
- **Октябрь в «Сверке Senet».** Колонка «Касса после смены» сравнивает остатки, поэтому покажет за октябрь и смены, проведённые не модулем. «Загрузить за период» с 01.10 заполняет историю, ничего не проводя.

## 6. Очередь «Разобрать»

### 6.1 Назначение

Очередь — единственное место, где модуль спрашивает человека. API не зависит от экрана: позже те же вызовы будет делать Telegram-бот (`answered_via = telegram`).

### 6.2 Причины

| Причина | Что ждёт ответа |
|---|---|
| `unrecognized` — правило не нашлось | Категория, контрагент, комментарий |
| `name_only` — только имя сотрудника | То же; подсказка «Зарплата, {сотрудник}» |
| `salary_no_name` — ЗП без имени, доплата без получателя | Контрагент (категория «Зарплата» предложена) |
| `rule_broken` — правило ссылается на архивную категорию или контрагента | Категория, контрагент |
| `no_kaspi` — в смене нет выноса kaspi | «Каспи не было» (закрыть) или «Указать Каспи: N ₸» — тогда в одной транзакции создаётся доход Каспи N, а доход Касса уменьшается на N |
| `negative_cash` — Касса < 0 | Суммы двух доходов вручную или «Не проводить доходы смены» |

### 6.3 Ответ

- **2–3 предложения** у каждого пункта — чистая функция:
  1. подсказка правила (`name_only`, `salary_no_name`);
  2. самая частая пара «категория, контрагент» у прошлых выемок с похожим комментарием (общие нормализованные слова);
  3. самая частая пара у выемок той же суммы за последние 30 дней.
- **Ответ** создаёт операцию по §4.4–§4.5 и закрывает пункт:
  - статус `answered`;
  - `answered_by` — пользователь;
  - `answered_via` — `web` или `telegram`.
- **«Запомнить для "{комментарий}"»** — галочка у `unrecognized`, `name_only`, `salary_no_name`, `rule_broken`. Создаёт правило типа «Точное» (`created_from_review = 1`): точный нормализованный комментарий → категория, контрагент, комментарий. Затем повторно применяет его к открытым пунктам с тем же комментарием — они закрываются сами.
- **«Пропустить»** — `dismissed`, операция не создаётся, выемке ставится «Не проводить повторно».
- **Права.** Отвечать может тот, кто может создавать операции в компании. Править правила — тот, кто может править справочники.
- **Пункт не дублируется:** одна выемка — один открытый пункт.
- **Сама закрывается**, если выемка стала распознаваться: например, владелец добавил алиас.

## 7. Расписание

| Режим | Как запускается |
|---|---|
| `local`, `vps`, `cloudflare`, `ngrok` | Задача `senet-sync` в `main.ts` рядом с `daily-backup`: cron `5 * * * *`, `inLine(db, …)`, `protect: true` |
| `vercel` | Маршрут `GET /api/v1/cron/senet` с `Authorization: Bearer CRON_SECRET`, по образцу `cron/routes.ts` |

**Vercel.**
- **Запасной суточный запуск.** На бесплатном плане Vercel Cron срабатывает раз в сутки: в `vercel.json` добавляется суточный запуск `/api/v1/cron/senet`.
- **Ежечасный запуск — внешний пингер:** `.github/workflows/senet-sync.yml`, расписание `5 * * * *`. Он вызывает маршрут через `curl` с тем же секретом из секретов репозитория (`CRON_SECRET`, `APP_URL`). В README — как его включить; GitHub может запускать его с опозданием на несколько минут.
- **Бюджет запуска** — 240 с из 300 с функции. Не уложились → следующие клубы ждут следующего запуска, запуск получает `partial` с причиной «Не уложились во время — продолжим через час».
- **Один запуск за раз.** Параллельный вызов маршрута отвечает «уже идёт». Блокировка — advisory lock Postgres; локально — `inLine`.

**Окно запроса** — §5.2 спецификации 2026-10-15:
- **начало** — самое раннее из «открытия самой ранней незакрытой смены» и «последнего забора − 26 ч»; при первом заборе — «Загружать с даты»;
- **`income_outcome`** берётся с запасом в сутки назад, чтобы выемки до начала первой смены окна попали в её окно — как в эталоне;
- **«Обновить сейчас» и «Загрузить за период»** — как в §5.4 спецификации 2026-10-15. «Загрузить за период» режется на отрезки по 7 дней.

## 8. Интерфейс

Тексты — по-русски, в стиле существующих экранов. На телефоне — как в остальных разделах:
- разделы настроек — списком;
- «Сверка Senet» — через «Ещё»;
- строки — карточками.

### 8.1 «Настройки» → «Интеграции» → Senet

- **Пункт «Интеграции»** — после «Пользователей» (`settings-sections.ts`), карточка «Senet», «+ Подключить Senet».
- **Окно подключения:**
  - «Название»;
  - «Адрес организации» — имя или ссылка на админ-панель `https://имя.admin-v2.enes.tech/`, правило `^[a-z0-9-]{1,63}$`; под полем — итоговый адрес;
  - «Способ входа» — «Логин и пароль Senet (рекомендуется отдельный пользователь только для отчётов)» или «Токен»;
  - «Проверить» — вход и `cashdesk_session` за сутки; показывает «Смен за сутки: N, последняя закрыта {время}». Сохранить можно только проверенное подключение.
- **После сохранения:**
  - пароль и токен не показываются никогда, только подсказка: логин или `••••{4 знака}`;
  - «Заменить данные входа»;
  - «Отключить»;
  - «Удалить» — только если ничего не проведено.
- **Клуб подключения** — «+ Клуб». Список клубов у админ-панели не исследован (§12.4), поэтому:
  - «Номер клуба Senet» (`office_id`) и «Номер кассы» (по умолчанию 1) вводятся вручную;
  - «Проверить клуб» показывает название офиса из отчёта.
- **Связи клуба:**
  - проект;
  - счёт кассы — по умолчанию «Касса {проект}»;
  - счёт Kaspi — по умолчанию «Kaspi {проект}»;
  - категория дохода смены;
  - «Загружать с даты» (§5.5);
  - «Постоянная разница кассы, ₸» (учёт − Senet, у владельца +88), по умолчанию 0.
- **«Правила разноски»** — вкладка карточки Senet, секции по типам §4.3:
  - «Сотрудники: алиасы» — алиас → контрагент, пометка «ошибочный»;
  - «Слова зарплаты, доплаты, стажёра»;
  - «Каспи»;
  - «Мастера» — алиас → контрагент, категория;
  - «Владельцы и семья» — слова, «алиасы владельца А», контрагенты А и Б;
  - «Обед» — слова, категория;
  - «Ключевые слова» — список с перетаскиванием порядка;
  - «Бар» — товары, «слова → поставщик», поставщик по умолчанию, категория;
  - «Точные правила» — с отметкой «из очереди».

  У каждой записи — «только для клуба» (необязательно).
- **«Проверить на истории»** — кнопка на вкладке правил:
  - прогоняет текущие правила по всем сохранённым выемкам клуба за выбранный период, ничего не записывая;
  - итог: «Распознано N из M»;
  - список нераспознанных с причиной;
  - список выемок, у которых правила дали бы **не то**, что сейчас в журнале.

### 8.2 Баннер доступа

Пока подключение в `key_rejected`, над «Журналом» и «Сверкой Senet» висит строка «Обновите доступ к Senet — забор остановлен» со ссылкой на подключение.

### 8.3 «Сверка Senet»

Место и отбор — §6.1 спецификации 2026-10-15: вкладка рядом с «Журналом», видна при подключении.

**Строка — смена:**

| Колонка | Содержание |
|---|---|
| Смена | «14.10 09:02 — 21:05», у открытой — «идёт» |
| Кассир | Логин Senet |
| Выручка | Senet и Σ транзакций; расхождение — значок с суммой |
| Каспи, Касса | Проведено / по Senet |
| Выемки | Проведено N из M, в очереди K |
| Касса после смены | «Senet + разница» и «журнал». Журнал — остаток счёта кассы на момент последней операции смены, включительно |
| Состояние | См. ниже |

**Состояние:**
- «Сходится»;
- «Касса расходится на N ₸»;
- «Разобрать: K»;
- «Не проводится» — смена раньше «Загружать с даты»;
- «Идёт»;
- «Senet изменил смену после проведения»;
- «Внесение ≠ остаток прошлой смены».

**Первая смена с расхождением кассы** подсвечивается, у отбора — ссылка «К первому расхождению». Так владелец нашёл ошибку разноски вручную.

**Раскрытая смена:**
- выемки — исходный комментарий, сработавшее правило, операция-ссылка, «Не проводить повторно»;
- внесения;
- доходы;
- предупреждения;
- «Перепровести доходы смены» (§5.4).

### 8.4 Очередь «Разобрать»

**Где:** вкладка «Разобрать (K)» внутри «Сверки Senet»; счётчик — и на вкладке верхнего меню.

**Карточка пункта:**
- смена;
- сумма;
- исходный комментарий;
- причина;
- предложения — кнопками (§6.3);
- поля «Категория», «Контрагент» (комбобоксы журнала), «Комментарий»;
- «Запомнить для "{комментарий}"»;
- «Провести» и «Пропустить».

- Время — ISO UTC.
- Все записи — в пределах компании.

  - Настройки типов — категории «Зарплата», «Обед», «Дивиденды», «Бар», контрагенты А, Б и поставщик по умолчанию — хранятся записями того же типа с пустым `pattern`.
- **`senet_review_items`:**
  - `id`, `shift_id`, `cash_move_id` (пусто у `no_kaspi`, `negative_cash`), `reason`, `suggestions` (JSON);
  - `status` (`open | answered | dismissed`), `answer` (JSON), `operation_id`;
  - `answered_by`, `answered_via` (`web | telegram`), `answered_at`, `created_at`.
  - Уникальность открытого пункта: `(shift_id, cash_move_id, reason)`.
- **`senet_sync_runs`** — как в §4.3 спецификации 2026-10-15, плюс `trigger = cron`.

**Каскады.** Удаление операции `deleted_at` не каскадирует на уровне базы. Проводка считается снятой, если её операция удалена (§5.3). Все запросы «что проведено» соединяют с `operations.deleted_at IS NULL`.

### 9.2 Сырые файлы

- Xlsx хранится в `FileStore`: ключ `senet/raw/{connection}/{report}/{from}_{to}_{sha256}.xlsx`.
- **`senet_raw`** описывает файл: `id`, `connection_id`, `report`, `office_id`, `from_date`, `to_date`, `fetched_at`, `status`, `file_key`, `sha256`.
- Повтор с тем же `sha256` не пишется.
- Хранение — 90 дней. Очищает ежедневное задание: `runDaily` на Vercel, ночная задача локально.

### 9.3 Данные для склада и аналитики

Повторный забор окна **заменяет** строки клуба за это окно: удаление и вставка в одной транзакции. На эти строки ничего не ссылается, поэтому ключи строк не нужны.

| Таблица | Источник | Поля |
|---|---|---|
| `senet_transactions` | `transactions` | `office_id`, `at`, `code`, `kind` (`sell | refund`), `amount`, `payment` |
| `senet_sold_items` | `soldItems` | `office_id`, `shift_id`, `at`, `item`, `qty` (пусто у чеков времени), `amount`, `payment`, `refund`, `comment` |
| `senet_bar_purchases` | разбор выемок бара (§4.3) | `cash_move_id`, `item_text`, `qty`, `price`, `amount`, `mismatch` |
| `senet_checks` | `checks` | `office_id`, `at`, `code`, `amount`, `used`, `workstation`, `guest_login`, `phone_hash`, `phone_mask`, `cashier` |

**Телефон гостя:**
- хранится только как HMAC-SHA256 с ключом, выведенным из секретного ключа (§10), и маска `+7 *** ** 12`;

## 10. Безопасность

- **Секретный ключ** — 32 байта:
  - локально — `data/secret.key`, права только владельца процесса, создаётся при первом подключении;
  - на Vercel — переменная `SECRET_KEY` (base64), обязательна при наличии подключений. Без неё «Подключить Senet» отвечает «Задайте SECRET_KEY в настройках Vercel».
- **Шифр** — AES-256-GCM. Шифруются пароль, токен и будущий Application Key (`credentials_secret`).
- **Отсечение из истории.** Колонки `*_secret` отсекает `sanitizeDiff` (`/password|hash|token|secret/`), как и поля `password`, `token` в теле запросов.
- **Наружу** — только `credentials_hint`. Заголовки и тела запросов к Senet в лог не пишутся. Ответы 401/403 не сохраняются: только код.
- **Ключ не совпадает** (восстановление на другой машине, другой `SECRET_KEY`) → подключение «Данные входа не расшифрованы — введите заново».
- **Адреса.**
  - Исходящие запросы — только на `https://{org}.app.enes.tech`, у будущего источника — на `{org}.api.enes.tech`.
  - `org` проходит правило §8.1. Перенаправления не выполняются.
  - `SENET_API_BASE` переопределяет адрес только для тестов и e2e.
- **Только чтение.** В клиенте Senet есть лишь запрос входа (`POST`) и `GET` отчётов. Остальных путей в коде нет.
- **Настоящие данные** — имена, логины, суммы, название организации — не попадают в репозиторий, тесты и снимки. Образцы — синтетические (§12.1).

## 11. Ошибки и тексты

| Случай | Статус | Текст |
|---|---|---|
| Неверный логин или пароль, 401 после повторного входа | `key_rejected` | «Senet не принял данные входа. Обновите их в настройках подключения» |
| Вход требует кода или SSO | `key_rejected` | «Senet просит подтвердить вход — подключитесь токеном» |
| Нет ответа, DNS, таймаут, 5xx | `unreachable` | Как в §8 спецификации 2026-10-15 |
| Незнакомый формат xlsx | `ok`, запуск `partial` | «Отчёт «{отчёт}» пришёл в незнакомом формате — сохранён для разбора» |
| Не уложились во время (Vercel) | `ok`, запуск `partial` | «Не уложились во время — продолжим через час» |
| Нет `SECRET_KEY` на Vercel | — | «Задайте SECRET_KEY в настройках Vercel» |

## 12. Тесты и приёмка

### 12.1 Образцы

- Синтетические xlsx с теми же колонками и выдуманными значениями. Собираются из кода тестов писателем xlsx (`xlsx-writer`): клуб «Клуб 1», кассир «Сотрудник А», сотрудники «Оператор 1…», владельцы «Владелец А/Б», поставщики «Поставщик 1…».
- Поддельный сервер Senet — Fastify на свободном порту, вход и отчёты.

### 12.2 Тесты

**Чистые функции:**
- окно смены, выемка до начала следующей смены;
- выручка и контроль по транзакциям;
- внесение ≠ остаток прошлой смены;
- Каспи и Касса: нет Каспи, отрицательная Касса;
- каждый тип правила: ошибочный алиас, `dop zp` с получателем и без, стажёр, дивиденды «только А / иначе Б», брак, разбор `товар×кол-во×цена` и несовпадение суммы, ограничение «только для клуба», архивная категория;
- порядок типов;
- время операций, в том числе без зарплат и с операцией из очереди;
- предложения очереди.

**Серверные тесты — на обоих диалектах:**
- вход и обновление токена при 401;
- 401 после входа → `key_rejected` и остановка забора;
- открытая смена пропускается и проводится после закрытия;
- идемпотентность: повторный забор;
- смена изменилась после проведения: новая выемка, пропавшая выемка, изменилась выручка, «Перепровести доходы смены»;
- удаление операции → повторная проводка; «Не проводить повторно»; «Отмена» удаления после замены отказывает;
- очередь: каждый ответ создаёт операцию; «Запомнить» создаёт правило и закрывает похожие пункты; `no_kaspi` с суммой; `answered_via`;
- «Проверить на истории» ничего не пишет;
- «Загружать с даты»;
- маршрут `cron/senet`: секрет, «уже идёт», бюджет времени;
- шифрование: в базе нет секрета открытым текстом, нет его в логах и истории; телефон — только хеш и маска;
- замена строк аналитики при повторном заборе окна;
- сырые файлы и их очистка.

**e2e на поддельном сервере (`SENET_API_BASE`):**
- подключение и клуб;
- забор и автопроводка;
- журнал;
- очередь;
- «Сверка Senet» и «К первому расхождению»;
- баннер доступа;
- телефон.

**Снимки `shots:ux`:**
- «Интеграции»;
- подключение;
- «Правила разноски»;
- «Проверить на истории»;
- «Сверка Senet»;
- раскрытая смена;
- «Разобрать».

### 12.3 Сверка с эталоном — только локально

`scripts/senet-parity.ts`:
- берёт xlsx из `.superpowers/senet-local/senet_raw/`;
- вызывает функции эталона (`build_shifts`, `shift_to_ops`) через короткую обёртку на Python. CLI эталона падает на текущем pandas (позиционный `sheet_name`), поэтому вызываются сами функции;
- переводит настройки эталона в правила модуля (`.superpowers/senet-local/rules.json`, только локально);
- прогоняет модуль и сравнивает операции по ключу «время, счёт, категория, контрагент, сумма, комментарий».

- Строки эталона с отметкой «проверить» сравниваются не с операциями, а с пунктами очереди. Пример: доход Каспи на 0 при отсутствии выноса — это пункт `no_kaspi`.

Тест сверки пропускается, если каталога нет.

**Критерии:**
- 0 расхождений по операциям за 08–31.10.2026;
- остаток кассы после каждой смены = «Сумма» Senet + 88.

Предварительный прогон эталона 2026-11-02: 48 смен, 209 операций, 1 пункт на проверку.

### 12.4 Пробный забор (первая задача плана)

С данными входа владельца, на его машине:
- отчёты `shop_quantity`, `movements_of_goods`, `office_load`, `office_load_by_zones` — колонки и ключи;
- есть ли в админ-API список офисов и касс. Если есть, «Номер клуба» станет выбором из списка;
- поведение токена после повторного входа: живёт ли прежний токен параллельно.

Сырые ответы остаются у владельца, в репозиторий попадают только описания колонок.

### 12.5 Приёмка с владельцем

На одном клубе (решение 6):
- **История.** «Загрузить за период» с 01.10 → «Сверка Senet» за октябрь без расхождений кассы, с учётом разницы +88.
- **Автопроводка.** Ставим «Загружать с даты» после последней смены теста. Следующая закрытая смена проводится сама в течение часа после закрытия — через пингер GitHub Actions.
- **Очередь.** Ответ с «Запомнить» → следующая такая выемка проводится сама.
- **Удаление.** Удалённая операция возвращается; с «Не проводить повторно» — нет.
- **Отказ доступа.** Неверный пароль → баннер и остановка; новые данные → забор возобновился.
