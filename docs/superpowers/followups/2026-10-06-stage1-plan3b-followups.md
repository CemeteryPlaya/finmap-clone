## Что сделано

- **Пользователи.**
  - Список и добавление; уникальность логина проверяется атомарно.
  - Переименование, сброс пароля, отключение и включение.
  - Сброс пароля и отключение завершают сессии пользователя в той же транзакции.
  - Себя и последнего активного пользователя отключить нельзя (422 `USER_LOCKOUT`, код внесён в §6.2). Проверка выполняется внутри транзакции.
- **Профиль.**
  - Смена имени.
  - Смена своего пароля: текущая сессия остаётся, остальные завершаются.
  - Лимит неудачных попыток — 5 за 15 минут; успешная смена пароля сбрасывает счётчик.
  - Если администратор одновременно сбросил пароль, смена своего пароля отклоняется с кодом 409 и не перезаписывает его сброс.
- **`npm run user:passwd`** — сброс пароля из консоли с бэкапом перед миграцией. Если пользователь отключён, скрипт об этом предупреждает.
- **История действий.**
  - API: лента компании и системная лента, фильтры по пользователю и сущности, постраничная загрузка, имя пользователя.
  - `/meta` отдаёт часовой пояс.
  - Экран показывает изменения в виде «было → стало».
- **Резервная копия.** Статус последней копии и путь `BACKUP_COPY_DIR`, кнопка «Скачать сейчас» (`fetch` → Blob, с заголовком `X-Requested-With`).
- **`user_preferences`.**
  - API: значения в JSON, лимит в байтах, не больше 50 ключей; изменения в историю не пишутся.
  - Запоминается последняя открытая компания; если она архивная или удалена, открывается первая активная.
- **Переключатель компаний.**
  - Управление с клавиатуры: стрелки, Home/End, Esc; фокус возвращается на кнопку.
  - Название компании входит в доступное имя кнопки (WCAG 2.5.3).
  - Выбор текущей компании не уводит из настроек; выбор другой открывает тот же раздел.
- **«Новая компания»** больше не мигает при загрузке.
- **E2E:** `e2e/service-screens.spec.ts`, 5 тестов. Логины уникальны, тесты можно повторять.

## Решения, принятые по ходу выполнения

1. **Одна волна итоговых правок:** тест конфликта при смене пароля, сброс счётчика попыток, настройки без повторных запросов, кнопки вместо вкладок на экране истории, лента не показывает данные другой ленты.
   Если решение неверно — откатывается один небольшой коммит `bf48cb8`.
2. **У входа и у смены пароля раздельные лимиты попыток.** Общий лимит позволил бы украденной сессии заблокировать настоящему пользователю вход.
   Если решение неверно — украденная сессия получает 5 лишних попыток угадать пароль за 15 минут.
3. **Тесты правок сделаны строже, чем в задании.**
   - Хэш пароля подменяется прямо в БД, чтобы проверка была детерминированной.
   - После успешной смены пароля идут 2 неверные попытки вместо 1: иначе тест прошёл бы и без исправления.

   Продуктовый код не затронут.

## На заметку для следующих этапов (безопасность)

- **«Все видят всё» и любой пользователь управляет пользователями.** Поэтому украденная сессия может захватить чужую учётную запись, не зная пароля: создать себе пользователя и сбросить пароль жертве. Все шаги видны в истории. В будущем можно требовать текущий пароль действующего пользователя для создания пользователя, сброса пароля и отключения. Это решение уровня спецификации, не дефект реализации.

## Отложенные мелкие замечания (бэклог)

**Сервер и тесты:**
- Схема разрешает логин до 64 символов, сервис — от 3 до 32 (сообщение сервиса правильное).
- `nextBeforeId` не пустой на последней полной странице: один лишний пустой запрос.
- `userName` в истории — текущее имя пользователя, а не имя на момент события.
- `JSON.parse` настроек не защищён от повреждённых данных.
- `updatedAt` вычисляется дважды.
- Не хватает тестов:
  - 401 для `/preferences`;
  - граничные значения ключа и размера;
  - неверный `beforeId`;
  - фильтры системной ленты;
  - сброс пароля без записи `update`;
  - смена пароля на тот же самый;
  - неверное имя в `PATCH`;
  - блокировка последнего активного пользователя через HTTP.

**Интерфейс:**
- Сообщения «Пароль изменён» и «Пароли не совпадают» остаются, пока пользователь вводит заново.
- Уведомление в строке пользователя не исчезает само.
- `formatBytes` на границе показывает «1024 КБ».
- `diffRows` показывает массивы по индексам.
- Ссылки в меню переключателя не реагируют на пробел.
- Куда уходит фокус после Tab в меню, зависит от браузера.
- Предупреждение `exhaustive-deps` на `[open]`.
- Имя файла с `filename*` (RFC 5987) не поддерживается, сервер его не отдаёт.
- Ссылка на Blob освобождается через 1 с.

**Вне плана 3b (шаги 5–8):**
- Кнопка истории и меню пользователя в шапке.
- Неудачный выход из системы сейчас считается выходом.
- Вошедший пользователь на `/login` не перенаправляется внутрь.
- Гонка между `user:add` из консоли и запущенным сервером.
