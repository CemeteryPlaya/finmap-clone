## Что сделано
- **Чтение файла без новых пакетов.**
  - **ZIP.** Сверяются:
    - конец каталога и его комментарий;
    - точный размер каталога;
    - пересечения записей;
    - локальный заголовок с каталогом;
    - CRC.

    Действуют пределы на запись, часть и весь архив. Отказ — у шифрования, ZIP64, опасных имён.
  - **Безопасный XML.** Без DTD и сущностей. Имена сущностей ищутся без прототипа. Атрибуты читаются одним проходом, без регулярных выражений с возвратами. Тег ограничен 64 КБ, есть проверка корня и полного имени закрывающего тега.
  - **Первый лист XLSX** — через связи книги. Учитываются общие строки, `t="str"`, ошибки ячеек, `date1904`. Предел 32 767 символов действует для любой ячейки, есть бюджет текста листа.
  - **CSV.** UTF-8 с BOM и без него, UTF-16LE, cp1251. UTF-16BE отклоняется (F8 «сохраните в UTF-8»). Разделитель выбирается по найденным заголовкам, кавычки по RFC 4180, есть пределы.
  - **Тип файла** определяется по содержимому, а не по расширению.
- **Формат Finmap.**
  - Заголовки распознаются с латинскими двойниками.
  - `nameKey`: регистр и «ё» не важны, двойники приводятся к кириллице, «Kaspi» остаётся латиницей.
  - Нет обязательной колонки или колонка повторяется — ошибка F6.
- **Разбор строк.**
  - **Тип** — по «Со счета» / «На счет».
  - **Суммы:**
    - запятая или точка;
    - разряды по три цифры;
    - 15 значащих цифр;
    - больше 16 цифр целой части — R07.
  - **Даты:**
    - числа Excel со временем и текст;
    - диапазон 01.03.1900–31.12.9999;
    - время Алматы, UTC+6 до 01.03.2024.
  - **Начисление** — дата или начало периода.
  - **Плановые строки** пропускаются с W1.
  - **Теги и комментарий.**
  - **Каталог ошибок и предупреждений** R/W/A/F на русском, сгруппирован, сначала ошибки.
- **Миграция 0006:** таблица `imports` и `operations.import_id`, без пересборки `operations`.
- **Сопоставление справочников.**
  - Счета, категории с подкатегориями и системные категории, контрагенты (тип — по категории), проекты, теги.
  - Архивные записи не сопоставляются (R17).
  - Строка с ошибкой ничего не добавляет в «Будет создано».
- **Предпросмотр.**
  - **Счета.** Новый — от текущего остатка или от стартового баланса. Существующий — с «Остатком после импорта» и переносом даты открытия.
  - **Пределы.** Не больше 1000 счетов (F9), название счёта до 120 символов (R13).
  - **Суммы.** Курсы и сумма в базовой валюте. Нулевая сумма зачисления — R06, переполнение — A4.
  - **Дубликаты** — с учётом повторов и строк разбиения.
  - **«Будет создано»** и план записи `ImportPlan` строятся только по строкам, которые реально будут добавлены.
- **HTTP.**
  - Загрузка до 30 МБ: предел срабатывает до разбора тела. Принимается только octet-stream, остальное — 415.
  - Подпись куки и CSRF проверяются до чтения тела.
  - Кэш проверки:
    - 30 минут, до 3 файлов;
    - бюджет около 150 МБ;
    - отдельно для каждого пользователя и компании;
    - хранит копию без ссылок на распакованный текст.
  - Повторная проверка — по токену, без новой загрузки.
  - Шаблон `template.xlsx` с листами «Шаблон» и «Инструкция».
  - Писатель XLSX с несколькими листами и общими строками.
- **Вложения.** Загрузка тоже принимает только octet-stream (415 для JSON и текста).

## Для плана И-2
- Клиент должен отправлять файл с `Content-Type: application/octet-stream` (как `lib/attachments.ts`), иначе 415.
- Кэш общий на сервер: 3 файла. Четвёртая загрузка вытесняет самую старую проверку, её владелец получает 410 «Проверка устарела» и загружает файл заново. Для нескольких пользователей это принято. Сообщение в панели должно быть понятным.
- `ImportPlan` уже содержит всё для записи одной транзакцией; повторно ничего выводить не нужно.
- В `bench:import` проверить время записи 16 000 строк и худший случай памяти кэша.

## Отложено (не блокирует)
1. **Просроченный, но подписанный сеанс** может заставить сервер прочитать до 30 МБ до ответа 401 (решение 20).
2. **«1,234» читается как 1,234** с предупреждением W10 — правило §4.2.
3. **ISO-даты с `Z` или смещением** дают R02: Finmap пишет даты числами.
4. **«Сегодня» фиксируется при загрузке.** Строка может остаться пропущенной после полуночи до новой проверки.
5. **Повторяющийся час 29.02.2024 в Алматы** берётся по первому вхождению.
6. **Синхронный разбор и предпросмотр под пределом 300 запросов в минуту** — допустимо по §9 и §10.
