# Этап 1, план 8b (надёжность перед установкой у клиента): итоги и отложенные замечания

**Ветка:** `stage1/plan1-skeleton`, коммиты b2bce03..91bc017. В диапазоне 4 задачи и волна финальных правок 91bc017.

## Что сделано
- **Сервер и `app.lock` после скачка часов.**
  - Если `app.lock` оставлен в прошлую загрузку, а порт занят, сервер выходит с кодом 4 (`LockSuspectError`). Супервизор не сдаётся: он повторяет запуск с паузой 1 → 60 с и пишет причину в журнал.
  - Блокировка, в которой записан PID самого процесса, но которую он не брал, считается устаревшей.
- **ngrok.**
  - Ошибки с кодом `ERR_NGROK_*` считаются окончательными. Исключение — коды занятой сессии 108/324/334: для них 8 попыток.
  - Ошибки сети повторяются как раньше.
  - Окончательная ошибка останавливает только туннель, приложение продолжает работать на этом компьютере.
- **`npm run setup` при работающем приложении.** Setup сохраняет настройки, закрывает права и подсказывает, что делать: `npm run stop` или сменить `PORT`. Базу не мигрирует, cloudflared не трогает.
- **cloudflared.**
  - `CLOUDFLARED_PATH`, указывающий на папку, отклоняется и в `npm start`. Неверный путь можно сбросить нажатием Enter.
  - `cloudflared` записывается атомарно.
- **Пересборка интерфейса.** Интерфейс пересобирается после `git pull`, если:
  - удалены файлы;
  - изменились `src/templates`;
  - изменились `vite.config.ts`, `package-lock.json` или `tsconfig.json`.
- **Права на данные.**
  - Linux: `data/` получает права 0700.
  - Windows: `npm run setup` закрывает `data\` и файл настроек через `icacls` (группы указаны по SID) и предупреждает, если проект лежит вне профиля пользователя.

## Отложено (не блокирует)
1. **Повторно использованный PID.** Другой node.exe с PID из блокировки, которую запись считает живой, всё ещё считается приложением (как в 8a, пункт 1). Также чужая программа на порту вместе с повторно использованным PID из `supervisor.lock` останавливает супервизор насовсем.
2. **Порядок в `setup.ts` без автотеста.** Не покрыты тестами порядок «настройки → icacls → проверка работы приложения» и сброс `CLOUDFLARED_PATH`: они проверены только чтением кода.
3. **icacls:**
   - пользователь берётся как `DOMAIN\name` из окружения, поэтому при запуске от имени другого администратора права получит не тот пользователь;
   - вывод `icacls` скрыт.

   Права папки `BACKUP_COPY_DIR` (там копии базы) не меняются.
4. **ngrok:**
   - код ошибки не ищется в `.cause`;
   - ошибки сети расходуют счётчик попыток занятой сессии.
5. **cloudflared:**
   - остаётся `.tmp` после сбоя;
   - нет `fsync` перед переименованием;
   - тесты оставляют временные папки.
6. **Пересборка и права на Linux:**
   - пересборка обходит всё дерево исходников при каждом запуске, временные файлы редактора вызывают лишнюю пересборку;
   - предупреждение `chmod` на Linux печатается дважды и не попадает в журнал.
7. **Тесты блокировок.** Если тест упадёт до `release()`, путь останется в наборе удерживаемых, и это может повлиять на следующие тесты.
