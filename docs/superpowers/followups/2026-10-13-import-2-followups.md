## Что сделано
- **Запись импорта одной транзакцией** (`BEGIN IMMEDIATE`).
  - Внутри транзакции проверка повторяется, поэтому в базу попадает ровно то, что пользователь видел в проверке. Версия проверки сверяется:
    - 409 — данные изменились, к ответу приложена свежая проверка;
    - 422 — в файле ошибки или «Нечего импортировать: все операции из файла уже есть в компании»;
    - 410 — проверка устарела.
  - Порядок записи: запись импорта → новые счета → изменения существующих счетов → категории (сначала родители) → контрагенты → проекты → теги → операции → история.
  - Операции пишутся подготовленными выражениями. Тест эквивалентности доказывает, что строки в базе такие же, как у обычного «Добавить операцию».
  - Писатель отказывает неверным операциям, а не записывает их молча.
- **Гонки и смена компании.**
  - Пусть два человека проверили один файл, где есть новый счёт. Когда второй нажмёт «Импортировать», получит «Счёт «X» уже есть в компании — проверка обновлена, выберите его», а после обновления — «Нечего импортировать». Дублей нет.
  - Архивность компании проверяется уже под блокировкой записи.
- **Панель «Импорт из Excel».**
  - Кнопка «Импортировать» — последней в тулбаре журнала, на телефоне — «Ещё» → «Импорт из Excel» на весь экран.
  - Файл можно перетащить или выбрать. Рядом ссылка «Скачать шаблон».
  - Проверка показывает итог «В файле N строк: доходов …, расходов …, переводов …, с ошибками …».
  - Карточки счетов:
    - сопоставить с существующим счётом;
    - создать новый — валюта и «Текущий остаток» либо «Стартовый баланс», с подсказкой «Стартовый баланс: X»;
    - «Создать новый счёт» недоступно, если счёт с таким названием уже есть.
  - Состояния: «Проверка устарела» (файл проверяется заново сам), «данные изменились», «Импорт завершён».
  - Панель привязана к своей компании:
    - при переходе в другую компанию закрывается;
    - если запись уже идёт, доводит её в своей компании;
    - если такая запись не удалась, показывает только «Импорт в «A» не выполнен» и «Закрыть».
  - Во время записи карточки недоступны. Окно не закрывается ни по Esc, ни по «Закрыть», ни по щелчку мимо.
  - Пропущенный мимо зоны файл не открывает браузер.
- **Импорт в «Истории действий»** — «Импорт».
- **`npm run import:check`** — сверка без записи в базу (`readonly`, одно чтение):
  - сравнивает файл и базу по счетам, категориям и количеству;
  - итоги: «Совпадает», «Расхождений: N» или «Не сверено: N»;
  - параметр `--today`.
- **`npm run bench:import`** на файлах размера настоящих (16 тыс. строк — 9,2 МБ; 50 тыс. — 29 МБ):

  | Файл | Загрузка | Проверка | Запись | Пик памяти | Бюджет |
  |---|---|---|---|---|---|
  | 16 тыс. строк | 1,4 с | 0,5 с | 1,4 с | 346 МБ | 400 МБ |
  | 50 тыс. строк | 4,0 с | — | 4,0 с | 475 МБ | 500 МБ |

- **README «Импорт из Finmap»** — пошагово, со сверкой.

## Как проверить на своих данных
По README «Импорт из Finmap»:
1. Выгрузите «Excel» из Finmap.
2. В Finmap посмотрите стартовый баланс и дату открытия каждого счёта.
3. Создайте у нас новую компанию.
4. В журнале нажмите «Импортировать» и выберите файл.
5. В каждой карточке счёта выберите «Создать новый счёт», KZT, «Текущий остаток» — остаток счёта в Finmap.
6. **Главная проверка:** подсказка «Стартовый баланс: X» на карточке должна совпасть со стартовым балансом этого счёта в Finmap.
   - Совпадение текущих остатков ничего не доказывает: «Текущий остаток» сам подгоняет стартовый баланс.
   - Ожидаемые стартовые балансы по вашей выгрузке разработчик сообщает отдельно — в репозиторий они не записываются.
7. Нажмите «Импортировать».
8. Запустите `npm run import:check -- …`. Если между импортом и сверкой прошли дни, добавьте `--today <день импорта>`.

Пока «Отменить импорт» нет (план И-3), повторяйте импорт в новой тестовой компании.

## Отложено (не блокирует)
1. **Мелкие отличия от Finmap во внешнем виде панели:**
   - нет линии под заголовком;
   - зона файла белая, а не серая;
   - иконка папки контурная;
   - у «Выберите файл» нет скрепки;
   - неактивная «Импортировать» бледно-зелёная.
2. **Запас памяти при 50 тыс. строк — 25 МБ** (475 из 500). Замерено на 16-ядерной машине. Если на слабой машине бюджет нарушится — вынести разбор в `worker_threads` (§15.3).
3. **Новый счёт с тем же названием, что у существующего, через импорт не создать** (R3). Нужно выбрать существующий счёт.
4. **Кэш проверок общий на сервер (3 файла).** Четвёртая загрузка вытесняет самую старую. Её владелец увидит «Проверка устарела», и файл проверится заново.
5. **«Назад» в браузере во время записи:** запись на сервере завершится, но экран результата не увидеть. В README об этом есть строка, блокировки перехода нет.
6. **M-4:** нет отдельного теста на «410 при другой неверной карточке».
7. **Файл с кросс-валютными переводами без «Суммы в валюте компании»** в `import:check` даёт «Не сверено». В спецификации отражено (becdd49).
8. **Не проверено на настоящем Finmap:**
   - названия системных категорий Finmap;
   - часовой пояс выгрузки (§15.4);
   - попадают ли в «Excel» плановые операции с прошлой датой.

   Сверка на ваших данных это покажет.
