# Этап 1, план 2 — итоги, решения исполнителя и хвосты

Ветка `stage1/plan1-skeleton`, коммиты `47f44de..77ee3a0` (поверх плана 1). План перед выполнением прошёл 4 раунда harness-review с реальным применением и прогоном тестов (итог APPROVE). Каждая из 7 задач прошла своё ревью. Финальное ревью вынесло вердикт «можно сливать после исправлений»; волна исправлений принята повторным ревью.

Проверка контроллера (HEAD `77ee3a0`): `npm run typecheck` — без ошибок, `npm test` — 177/177, `npm run test:e2e` — 5/5. В `main` не сливаем до завершения всех работ (решение заказчика).

## Что сделано

- **Шаблоны.** 9 системных статей, у каждой связь с типом контрагента. Шаблоны `general` («Общий») и `computer-club` («Компьютерный клуб»): статьи, счета «Касса/Kaspi {проект}» (KZT), параметры «Количество ПК» и «Количество консолей», интеграция `senet`, 4 метрики.
- **Миграция 0001.** Таблицы `companies`, `projects`, `accounts`, `categories` с уникальностью по `(компания, вид, templateRef)` и `(компания, вид, systemKey)`. Тест проверяет, что перед миграцией создаётся бэкап.
- **Компании.** Создание вместе с системными статьями, правка, архив (только если все счета компании в архиве). Архивная компания доступна только для чтения.
- **Проекты по шаблону.** Создание в одной транзакции: статьи шаблона вливаются без дублей, создаются счета с `openedAt` по `APP_TIMEZONE`, пишется история. Есть правка (параметры сливаются с сохранёнными), архив, запрет дублей названия внутри компании, чтение статей и счетов. Всё проверяется по компании, чужие id дают 404.
- **Интерфейс.**
  - Экран «Создайте первую компанию», с кнопкой «Отмена», если активные компании уже есть.
  - Переключатель компаний, вкладки «Журнал» и «Настройки».
  - Настройки «Проекты»: форма из `paramsUi`, проверка той же zod-схемой, что на сервере.
  - Настройки «Компании».
  - Если сервер вернул 401, приложение переводит на страницу входа. При сбое фонового обновления остаются уже загруженные данные.

## Решения, принятые по ходу выполнения

1. **В волну исправлений после финального ревью включено:**
   - данные отображаются раньше ошибки, глобальная обработка 401;
   - сброс устаревших ошибок форм;
   - кнопка «Отмена» на экране новой компании;
   - запрет дублей названия проекта;
   - слияние `templateParams` при `PATCH`;
   - проверка `APP_TIMEZONE` при старте;
   - тест отката при создании проекта и тест границы суток 23:30.

   Если это решение неверно, дубли названий проектов придётся снова разрешить. Переименование счетов при переименовании проекта и связи полей с ошибками для экранного диктора перенесены в план 3.
2. **Порядок и удаление проектов, а также `GET /companies/summary`** сознательно отложены (план 3 и шаг 4). Это записано в самом плане.

## Обязательно в плане 3 (до появления соответствующих API и экранов)

- **`accounts.create` принимает архивный проект.** Нужна проверка инварианта 7: ответ `ARCHIVED_REFERENCE`.
- **`openedAt` проверяется только по формату**, дата `2026-02-31` проходит. Нужна проверка, что такая календарная дата существует.
- **API записи статей.** Родитель должен быть из той же компании и того же вида, глубина не больше 2. Если пользователь перенёс группу шаблона, слияние нового шаблона не должно создавать третий уровень или класть детей в архивную группу.
- **Общий помощник для изменений справочников.** Изменение и запись в историю выполняются в одной транзакции. Сейчас изменение и архив компаний и проектов пишут историю отдельно.
- **Экраны настроек.**
  - Сначала показываются данные, потом ошибка: это есть в разметке компании, но ещё не в `ProjectsSettings` и `CompaniesSettings`.
  - Поля с ошибками связаны через `aria-invalid` и `aria-describedby`.
  - Ошибки разбора чисел выводятся по-русски, `Number()` принимает `"1e3"`.
- **Переключатель компаний.**
  - Навигация стрелками и возврат фокуса.
  - `aria-label` не должен скрывать название текущей компании (WCAG 2.5.3).
  - Выбор текущей компании не должен уводить из настроек.
- **Мелочи.**
  - В ошибке `APP_TIMEZONE` префикс выводится дважды.
  - Обработчик 401 не должен перезагружать страницу при первом заходе без сессии: пропускать запрос `me`.
  - При переименовании проекта нужно предложить переименовать счета «Касса/Kaspi …».
- **Тесты.**
  - Межкомпанейный `listTree`.
  - Вариант RF3 шире: чужие `unarchive` и счета, нет записи в истории.
  - `/templates` не отдаёт схемы.
  - Подстановка базовой валюты для счёта шаблона.
  - Внешние ключи `categories.parent_id` и `accounts.project_id`.
