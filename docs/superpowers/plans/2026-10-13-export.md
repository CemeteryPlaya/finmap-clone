# Экспорт и импорт, план Э: экспорт как в Finmap — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** последний план спецификации импорта и экспорта (§14): меню «Экспортировать в» с пунктами «Excel» и «Собрать Excel»; файл «Excel» в формате Finmap, который загружается и в клон, и в Finmap; окно «Собрать Excel» со своим набором и порядком колонок; круг «выгрузка из клона → загрузка в клон» с совпадающими балансами и итогами по категориям.
- **Сервер:**
  - `GET …/operations/export.xlsx?format=finmap` — 16 колонок шаблона импорта, лист `ExportRU`, разбитая операция — строкой на каждую строку, период начисления зарплаты, налогов и НДС;
  - `format=custom&columns=…` — выбранные колонки в заданном порядке, строка «Итого», группа «Остатки и валюты»;
  - `GET …/operations/export-preview` — текст колонок у первых 3 операций для окна.
- **Клиент:** «Ещё» → «Экспорт» → «Экспортировать в»; окно «Собрать Excel» (превью, чипы по группам, перетаскивание и Alt+←/→, «×», «Собрать файл», запоминание набора); «Экспортировать в Excel» в окне «Фильтры» на телефоне.
- **Сверка:** тест круга через настоящий импорт; поправка `import:check` для переводов между валютами; README «Экспорт и круг»; чек-лист проверки вместе с владельцем (не шаг плана); `shots:ux` — `c40`, `c43`.

**Предусловие:** ветка `stage1/plan1-skeleton` на коммите этого плана (после fd10ce9). Ожидаемо на старте:
- `npm test` — 1063 пройдено и 1 пропущен;
- `npm run typecheck` — без ошибок;
- `npm run test:e2e` — 168 из 168;
- `npm run shots:ux` — 56 из 56;
- `npm run bench:import` — в бюджете.

**Architecture:**
- **Каталог колонок** — `src/shared/export-columns.ts`: 20 идентификаторов, общих у сервера и окна. Колонки Finmap берут названия у `FINMAP_COLUMNS` (`src/shared/finmap-format.ts`), поэтому заголовки файла, шаблон импорта и чипы окна не расходятся.
- **Сервер, `src/server/modules/operations/`:**
  - `journal-export.ts` — чистые функции над `ExportOperation` (названия справочников вместо идентификаторов, строки операции с родителем категории и системным ключом): `finmapSheet`, `customSheet`, `customPreview`, `accrualPeriod`. Значение каждой колонки «Собрать Excel» — одна запись, из которой берутся и ячейка файла, и текст превью;
  - `journal.ts` — выборка операций (`exportRows`, `completeExportRows`), `exportXlsx` (оба формата, имя файла, предел), `exportPreview`;
  - `routes.ts` — `GET …/export.xlsx` и `GET …/export-preview`.
- **Клиент:**
  - `lib/export-columns.ts` — чистые функции набора колонок (тесты в node);
  - `components/journal/ExportBuilderDialog.tsx` — окно; `MoreMenu.tsx` — раздел «Экспортировать в» и хозяин окна;
  - `lib/journal-filter.ts` — `journalExportHref(…, format, columns)`; `lib/queries.ts` — `useExportPreview`.
- **Круг:** `tests/server/export-roundtrip.test.ts` и общий помощник `tests/helpers/imports.ts` (`importXlsx`).

**Tech Stack:** Node 24, TypeScript, Fastify 5, zod 4, Drizzle 0.45 + better-sqlite3, React 19, TanStack Query 5, Tailwind 4, Vitest, Playwright. Новых пакетов нет.

## Решения, принятые при планировании

Записаны в спецификацию (§14, блок «Решения планирования плана Э», №1–№17) тем же коммитом, что и план.

1. **Задачи — 6 вместо 5.** Порядок §14 сохранён, но границы — по поведению:
   1. «Excel» в формате Finmap (сервер);
   2. «Собрать Excel» на сервере: `format=custom`, колонки, «Итого», превью;
   3. меню «Экспорт» и окно «Собрать Excel» (чипы, превью, «Собрать файл», запоминание набора);
   4. порядок колонок: перетаскивание, Alt+←/→, «×»;
   5. круг и сверка `import:check`;
   6. README, чек-лист владельца, `shots:ux`.

   Меню и окно — одна задача: пункт «Собрать Excel» без окна был бы мёртвой кнопкой. Проверка §12 вместе с владельцем (пятая задача §14) — не шаг плана: это чек-лист в `docs/superpowers/followups/` (решение 16).
2. **Параметры выгрузки (уточнение §8.3).**
   - `format` — `finmap` (по умолчанию, пустое значение — то же) или `custom`; другое — 400.
   - `columns` — повтор ключа, порядок сохраняется, без повторов, от 1 до 20 известных идентификаторов; неизвестный или повтор — 400 (`columns.N: «Неизвестная колонка»`, `columns: «Колонки не должны повторяться»`). Идентификаторы проверяются при любом `format`; у `finmap` колонки на файл не влияют.
   - `custom` без колонок — 400 `columns: «Выберите хотя бы одну колонку»`.
   - Прежний лист «Операции» (колонки журнала) удалён вместе с `journalSheet`: его колонки — подмножество чипов.
3. **Превью — запросом к серверу (уточнение §8.3).** Вместо `GET …/operations?limit=3` окно запрашивает `GET …/operations/export-preview` (фильтр и сортировка журнала, без страниц) и получает `{ rows: Record<id, string>[] }`: у первых 3 операций — текст каждой из 20 колонок каталога. Причина: превью обязано совпадать с файлом (знак суммы, период начисления, «; » у разбитой операции, остатки после операции), а по строкам журнала с идентификаторами клиент пересчитывал бы это сам и расходился бы с сервером. Колонки в окне выбираются и переставляются без запросов: сервер всегда отдаёт все 20.
4. **Каталог колонок** — `src/shared/export-columns.ts`, общий у сервера и окна: 20 идентификаторов. 14 колонок Finmap называются по полям `FinmapField` (`paidAt`, `accrualDate`, `periodFrom`, `periodTo`, `amount`, `baseAmount`, `fromAccount`, `toAccount`, `category`, `subcategory`, `counterparty`, `project`, `tags`, `comment`), 6 «наших» — `type`, `currency`, `balanceAfter`, `toAmount`, `toCurrency`, `toBalanceAfter`. Названия в чипах и заголовках «Собрать Excel» — заголовки шаблона без звёздочки; в «Excel» (§8.2) — заголовки шаблона со звёздочками. По умолчанию — 14 колонок Finmap.
5. **«Дата начисления» в «Собрать Excel» пишется всегда (уточнение §8.2).** Период «с» и «по» — по правилу §8.2, но «Дату начисления» он не обнуляет: набор колонок свободный, и без колонок периода дата сделки зарплаты пропала бы из файла; у Finmap в превью заполнены и дата, и период (`43-export-custom.png`). В «Excel» формата Finmap — как в §8.2: при периоде «Дата начисления» пуста. Дата и период в одной строке при загрузке дают предупреждение W6 (одна и та же дата).
6. **«Итого» (уточнение §8.3).**
   - «Сумма в валюте компании» — сумма значений колонки со знаком (переводы входят без знака, как записаны).
   - «Сумма в валюте счета» — если у всех операций одна валюта счёта; «Сумма зачисления» — если у всех переводов одна валюта зачисления.
   - Подпись «Итого» — в первой колонке без суммы; если все колонки с суммами — подписи нет.
   - Сумма вне безопасного целого — ячейка пуста. Операций нет — строки «Итого» нет, книга — один заголовок.
7. **«Excel»: строки и переводы (уточнение §8.2).** Разбитая операция — строка на строку операции. Перевод — одна строка с суммами самой операции, проект — из его единственной строки; категория, контрагент и дата начисления не пишутся. Операция без строк — одна строка с суммами операции. Суммы в «Excel» положительные: тип операции следует из «Со счета» и «На счет» (в «Собрать Excel» суммы со знаком, §8.3).
8. **Теги в обоих файлах через «, »** (импорт делит по запятой, §4.8); прежняя выгрузка писала «; ».
9. **Писатель.** `XlsxCell` получает `bold` (текст и число); в `styles.xml` три полужирных числовых формата (стили 8–10: 0, 2 и 3 знака). Файлы обоих видов пишутся с общими строками (`strings: 'shared'`).
10. **Меню (уточнение §8.1).**
    - В «Ещё» значок ⤓ — кнопка «Экспорт» (`aria-label`, `aria-expanded`); раздел «Экспортировать в» раскрывается в той же панели рядом с «Колонками» (независимо от них): ссылка «Excel» и кнопка «Собрать Excel».
    - «Excel» закрывает панель после начала скачивания (`setTimeout(0)`: ссылка до этого остаётся в странице); «Собрать Excel» закрывает панель и открывает окно. Окно живёт в `MoreMenu`, а не в панели: панель закрывается, окно остаётся.
    - Фокус и после ссылки, и после окна возвращается на «Ещё».
    - На телефоне — «Экспортировать в Excel» (формат Finmap) в «Ещё условия»; «Собрать Excel» там нет.
    - Ссылки всегда с `format`: `finmap` или `custom`; старой ссылки без него в интерфейсе нет.
11. **Окно «Собрать Excel» (уточнение §8.3).**
    - Набор колонок берётся из настройки `export.columns` один раз при открытии (неизвестные id и повторы отбрасываются, пусто — набор по умолчанию).
    - Набор запоминается только при «Собрать файл»; «Отмена», «×» и Esc его не меняют.
    - «Собрать файл» — ссылка-скачивание (`download`) с `aria-disabled`, если колонок нет; причина — в описании. Сбой записи настройки файл не отменяет.
    - Превью запрашивается при каждом открытии заново. Ошибка превью показывается в окне (`role="alert"`), файл всё равно собирается.
    - Предел 50 000 операций: ссылка, как у «Excel», получает от сервера JSON 422 `EXPORT_LIMIT` — браузер скачает его как файл ошибки. Так было и до плана Э (открытый риск).
12. **Порядок колонок (уточнение §8.3).**
    - Перетаскивание — за ручку в заголовке, событиями указателя с захватом и тем же приёмом, что `SettingsList` (мышь и касание одним кодом): `dropIndexAt` и `edgeScrollStep` из `lib/settings-list.ts` работают по оси X; у края таблицы она прокручивается сама. Esc отменяет перетаскивание и не закрывает окно.
    - Клавиатура — Alt+← / Alt+→ на ручке; итог объявляется в живой области: «Сумма в валюте счета — колонка 3 из 12». «×» объявляет «Колонка «Тип» убрана. Осталось колонок: 5», фокус переходит на ручку ближайшей колонки (последняя убрана — на первый чип).
    - Ручка и «×» — настоящие кнопки с именами «Переместить колонку …» и «Убрать колонку …».
13. **Круг (§11.2, §12 шаг 7).**
    - Тест экспортирует «Excel» из синтетической компании и импортирует файл настоящим кодом (`upload` → `preview` → запись) в новую компанию.
    - Счета новой компании создаются с тем же стартовым балансом (режим «Стартовый баланс», а не «Текущий остаток»): остатки проверяются, а не подгоняются.
    - Сравниваются балансы счетов, итоги по (вид, категория → подкатегория) и по проектам, и каждая строка источника — операция новой компании (момент, счета, суммы, категория, проект, контрагент, теги, комментарий, дата начисления). Разбитая операция возвращается N операциями.
    - Перевод USD → KZT возвращается точно (зачисление — из «Суммы в валюте компании»). Перевод KZT → USD — точно только при курсовой сумме зачисления; введённая не по курсу пересчитывается (§8.2), тест это фиксирует.
    - Демо-набор: балансы совпадают у всех счетов, кроме получателей переводов между валютами; у них разница ровно в сумме пересчётов зачисления.
14. **`import:check` (правка к решению 16 плана И-2).** Счёт, на который зачислен перевод между валютами без «Суммы в валюте компании» (зачисление считается по нашим курсам и в файле его нет), помечается в таблице «? », в `CheckLine.unverified`, и не входит в расхождения; в «Внимание» — «Движение этих счетов не сверялось: …»; итог — «Не сверено». Без правки круг с переводом в валюту, отличную от базовой, давал ложное «Расхождений».
15. **Снимки.** `shots:ux` — 58 экранов: `c40-export-click` (пара `40-export-click`, «Ещё» с раскрытым «Экспортировать в») и `c43-export-custom` (пара `43-export-custom`, окно «Собрать Excel» с превью). Сценарии стоят до импортов: сценарий истории импортов остаётся последним — он меняет данные демо-компании.
16. **Проверка §12 вместе с владельцем — не шаг плана.** Исполнители не трогают живое приложение (порт 3457), демо (порт 3460) и `data/`. Контролёр передаёт владельцу чек-лист `docs/superpowers/followups/2026-10-13-export-owner-checklist.md` (его создаёт задача 6; раздел «Экспорт и круг» README описывает те же шаги). Итог проверки владелец записывает в чек-лист без реальных сумм и названий.
17. **README (задача 6).** Раздел «Экспорт и круг»: формат «Excel», разбитые операции, период зарплаты и налогов, перевод между валютами, «Собрать Excel», пределы; **комментарий** — у нас до 2 000 знаков, у Finmap до 1 000: длинный комментарий пишется целиком, Finmap такую строку не примет (§8.2); как пройти круг вручную и через Finmap (§12 шаги 7–8); `import:check` и несверенные счета.

## Global Constraints

- **Без новых npm-пакетов и сети.** Только то, что уже есть: `adm-zip` (писатель XLSX), `better-sqlite3`, Drizzle, React, TanStack Query, Playwright.
- **Файл «Excel» (§8.2):**
  - ссылка без побочных эффектов: `GET …/operations/export.xlsx?format=finmap&…фильтр`; без `format` — как `finmap`;
  - имя файла — «{Компания} - Журнал - ДД-ММ-ГГГГ ЧЧ-ММ.xlsx» (время по `APP_TIMEZONE`, символы `\ / : * ? " < > |` и управляющие — «_»); лист `ExportRU`; строки «Итого» нет; строка заголовков закреплена;
  - заголовки — ровно тексты шаблона (§2.1), кириллицей, со звёздочками у обязательных: «Дата платежа*», «Дата начисления», «Период начисления (дата "с")», «Период начисления (дата "по")», «Сумма в валюте счета*», «Сумма в валюте компании», «Со счета*», «На счет*», «Категория», «Подкатегория», «Контрагент», «Подконтрагент», «Проект», «Подпроект», «Теги», «Комментарий»;
  - A — число Excel с долей суток, формат `dd.mm.yyyy hh:mm`, точно до секунды по часам `APP_TIMEZONE`; B — дата числом; C и D — текстом «01.09.2026 00:00:00» и «30.09.2026 23:59:59» у зарплаты, налогов и НДС с датой начисления 1-го числа; E и F — положительные числа; теги — через «, »; комментарий — целиком;
  - тексты — общими строками (`sharedStrings.xml`); текст, начинающийся с `=`, `+`, `-`, `@`, табуляции или CR, — со стилем `quotePrefix`; формул в книге нет;
  - не больше 50 000 операций (`JOURNAL_EXPORT_MAX`): больше — 422 `EXPORT_LIMIT` «Больше 50 000 операций — сузьте период или фильтр».
- **«Собрать Excel» (§8.3):**
  - только компьютер; окно `max-w-[1280px]` на `Modal`, заголовок «Собрать Excel», подпись «Перетащите заголовок колонки, чтобы изменить порядок. В превью — первые операции журнала.»;
  - «Что выгрузить» — чипы-переключатели (`aria-pressed`) в группах (`role="group"` с подписью): «Операция», «Счета», «Категории», «Контрагенты», «Проекты», «Теги и комментарий», «Остатки и валюты»; «Статус (план/факт)», «Подконтрагент» и «Подпроект» не показываются;
  - по умолчанию — 14 колонок Finmap без «Тип» и без «Остатков и валют»; набор и порядок — в настройке пользователя `export.columns` (`PUT /preferences/export.columns`);
  - кнопки «Отмена» и «Собрать файл»; без колонок «Собрать файл» недоступна (`aria-disabled`);
  - файл: лист «Журнал», одна строка на операцию, суммы со знаком (расход — минус, перевод — без знака), последняя строка «Итого» полужирным, значения — не формулы.

import { readXlsx } from '../../src/server/modules/imports/xlsx-read';

/**
 * Первый лист книги — строки значений текстом, как в файле (числа — как в `<v>`); пустые ячейки — ''. Ширина — по самой
 * широкой строке. Читает тот же разборщик, что у импорта: проверка выгрузки и круга идёт через настоящий код чтения.
 */
export function sheetRows(data: Buffer): string[][] {
  const rows = readXlsx(data).rows;
  const width = Math.max(0, ...rows.map((r) => Math.max(-1, ...r.cells.keys()) + 1));
  return rows.map((r) => Array.from({ length: width }, (_, c) => r.cells.get(c)?.value ?? ''));
}

const DAY_MS = 86_400_000;

/** Минимальные единицы → десятичная запись без округления и экспоненты: (-150050, 2) → «-1500.50». */
export function minorToDecimal(minor: number, minorUnits: number): string {
  const abs = String(Math.abs(minor)).padStart(minorUnits + 1, '0');
  const int = minorUnits > 0 ? abs.slice(0, -minorUnits) : abs;
  const frac = minorUnits > 0 ? `.${abs.slice(-minorUnits)}` : '';
  return `${minor < 0 ? '-' : ''}${int}${frac}`;
}

/** Момент → дата и время Excel по часам APP_TIMEZONE (дни от 30.12.1899 с долей суток). */
export function excelDateTime(iso: string, timeZone: string): number {
  const t = Date.parse(iso);
  return (t + zoneOffsetMs(t, timeZone) - EXCEL_EPOCH) / DAY_MS;
}

/** Календарная дата `YYYY-MM-DD` → дата Excel. */
export function excelDate(date: string): number {
  const [y, m, d] = date.split('-').map(Number) as [number, number, number];
  return (Date.UTC(y, m - 1, d) - EXCEL_EPOCH) / DAY_MS;
}

/** Системные категории, у которых дата начисления первого числа месяца уходит периодом (§8.2): зарплата, налоги, НДС. */
const PERIOD_KEYS: readonly SystemKey[] = ['salary', 'tax', 'vat'];

/**
 * Период начисления (§8.2): у зарплаты, налогов и НДС дата начисления — первое число месяца — уходит периодом «с — по»
 * текстом, как в выгрузке Finmap: «01.09.2026 00:00:00» — «30.09.2026 23:59:59». При импорте период возвращается в то же
 * `accrualDate` (§4.3). Другая категория или другое число — null: дата уходит в «Дату начисления».
 */
export function accrualPeriod(accrualDate: string | null, keys: readonly (SystemKey | null)[]): { from: string; to: string } | null {
  if (!accrualDate?.endsWith('-01')) return null;
  if (!keys.some((k) => k !== null && PERIOD_KEYS.includes(k))) return null;
  const [y, m] = accrualDate.split('-').map(Number) as [number, number];
  const last = new Date(Date.UTC(y, m, 0)).getUTCDate();
  return { from: `01.${pad2(m)}.${y} 00:00:00`, to: `${pad2(last)}.${pad2(m)}.${y} 23:59:59` };
}

  const units = getCurrency(currency).minorUnits;
  return { kind: 'number', value: minorToDecimal(minor, units), decimals: units };
};

 * (несколько строк) — строка на каждую строку операции: сумма, категория и проект — строки, остальное повторяется. Суммы
 * положительные; тип следует из «Со счета» и «На счет». У перевода категория, контрагент и дата начисления не пишутся.

export function finmapSheet(ops: ExportOperation[], baseCurrency: string, timeZone: string): XlsxSheet {
  const rows: XlsxCell[][] = [];

    const paidAt: XlsxCell = { kind: 'datetime', value: excelDateTime(o.paidAt, timeZone) };

    for (const line of parts) {
      const period = transfer ? null : accrualPeriod(o.accrualDate, [line?.systemKey ?? null]);
      const cells: Record<FinmapField, XlsxCell> = {
        paidAt,
        accrualDate: transfer || period || !o.accrualDate ? null : { kind: 'date', value: excelDate(o.accrualDate) },
        periodFrom: textCell(period?.from),
        periodTo: textCell(period?.to),
        amount: moneyCell(transfer || !line ? o.amount : line.amount, o.currency),
        baseAmount: moneyCell(transfer || !line ? o.baseAmount : line.baseAmount, baseCurrency),
        fromAccount: textCell(o.type === 'income' ? null : o.accountName),
        toAccount: textCell(o.type === 'income' ? o.accountName : transfer ? o.toAccountName : null),

        subcategory: transfer ? null : textCell(line?.parent ? line.category : null),
        counterparty: transfer ? null : textCell(o.counterpartyName),
        subcounterparty: null,
        project: textCell(line?.project),
        subproject: null,
        tags: textCell(o.tags.join(', ')),
        comment: textCell(o.comment),
      };
      rows.push(FINMAP_COLUMNS.map((c) => cells[c.field]));
    }
  }
  return {
    name: FINMAP_SHEET_NAME,
    columns: FINMAP_COLUMNS.map((c) => ({ header: c.header, width: FINMAP_WIDTH[c.field] })),
    rows,
  };
}

import { EXPORT_COLUMNS_DEFAULT, isExportColumnId, type ExportColumnId } from '../../shared/export-columns';

/**
 * Набор колонок окна «Собрать Excel» (§8.3 спецификации импорта): чистые функции, тесты — в node без DOM.
 */

/** Ключ настройки пользователя (`user_preferences`): массив id колонок в порядке файла. */
export const EXPORT_COLUMNS_PREF = 'export.columns';

/**
 * Набор из сохранённой настройки: неизвестные id и повторы отбрасываются, порядок сохраняется. Нет настройки, она не
 * массив или после отбрасывания пуста — набор по умолчанию (все колонки Finmap).
 */
export function savedExportColumns(pref: unknown): ExportColumnId[] {
  if (!Array.isArray(pref)) return [...EXPORT_COLUMNS_DEFAULT];
  const columns: ExportColumnId[] = [];
  for (const x of pref) if (isExportColumnId(x) && !columns.includes(x)) columns.push(x);
  return columns.length > 0 ? columns : [...EXPORT_COLUMNS_DEFAULT];
}

/** Чип: включённая колонка добавляется в конец, выключенная убирается; порядок остальных не меняется. */
export function toggleExportColumn(columns: readonly ExportColumnId[], id: ExportColumnId): ExportColumnId[] {
  return columns.includes(id) ? columns.filter((c) => c !== id) : [...columns, id];
}

/**
 * Набор колонок окна «Собрать Excel» (§8.3 спецификации импорта): чистые функции, тесты — в node без DOM.
 */

/** Ключ настройки пользователя (`user_preferences`): массив id колонок в порядке файла. */
export const EXPORT_COLUMNS_PREF = 'export.columns';

/**
 * Набор из сохранённой настройки: неизвестные id и повторы отбрасываются, порядок сохраняется. Нет настройки, она не
 * массив или после отбрасывания пуста — набор по умолчанию (все колонки Finmap).
 */
export function savedExportColumns(pref: unknown): ExportColumnId[] {
  if (!Array.isArray(pref)) return [...EXPORT_COLUMNS_DEFAULT];
  const columns: ExportColumnId[] = [];
  for (const x of pref) if (isExportColumnId(x) && !columns.includes(x)) columns.push(x);
  return columns.length > 0 ? columns : [...EXPORT_COLUMNS_DEFAULT];
}

/** Чип: включённая колонка добавляется в конец, выключенная убирается; порядок остальных не меняется. */
export function toggleExportColumn(columns: readonly ExportColumnId[], id: ExportColumnId): ExportColumnId[] {
  return columns.includes(id) ? columns.filter((c) => c !== id) : [...columns, id];
}

/** Alt+← / Alt+→ на ручке заголовка: колонка встаёт на соседнее место; на краю и не из набора — null. */
export function shiftExportColumn(columns: readonly ExportColumnId[], id: ExportColumnId, delta: -1 | 1): ExportColumnId[] | null {
  const i = columns.indexOf(id);
  const j = i + delta;
  if (i < 0 || j < 0 || j >= columns.length) return null;
  const next = [...columns];
  [next[i], next[j]] = [next[j]!, next[i]!];
  return next;
}

/**
 * Колонку id отпустили на место index среди остальных колонок (0 — первой, длина остальных — последней): новый порядок;
 * то же место и колонка не из набора — null.
 */
export function dropExportColumn(columns: readonly ExportColumnId[], id: ExportColumnId, index: number): ExportColumnId[] | null {
  if (!columns.includes(id)) return null;
  const others = columns.filter((c) => c !== id);
  const at = Math.max(0, Math.min(index, others.length));
  const next = [...others.slice(0, at), id, ...others.slice(at)];
  return next.every((c, i) => c === columns[i]) ? null : next;
}

/** Объявление после перестановки: «Сумма в валюте счета — колонка 3 из 12». */
export function columnPositionText(columns: readonly ExportColumnId[], id: ExportColumnId): string {
  return `${exportColumnLabel(id)} — колонка ${columns.indexOf(id) + 1} из ${columns.length}`;
}

/** Объявление после «×»: «Колонка «Тип» убрана. Осталось колонок: 5». */
export function columnRemovedText(id: ExportColumnId, left: number): string {

export function focusIndexAfterRemove(columns: readonly ExportColumnId[], id: ExportColumnId): number | null {

  return left <= 0 || i < 0 ? null : Math.min(i, left - 1);

interface SnapRow {
  comment: string | null;
  type: 'income' | 'expense' | 'transfer';
  paidAt: string;

/** Операции по строкам: у разбитой — строка на строку (так она возвращается после круга), у остальных — одна. */
function lineSnapshot(cid: number): SnapRow[] {
  const tags = new Map<number, string[]>();
  for (const t of all<{ id: number; name: string }>(
    'SELECT ot.operation_id AS id, t.name AS name FROM operation_tags ot JOIN tags t ON t.id = ot.tag_id JOIN operations o ON o.id = ot.operation_id WHERE o.company_id = ?',
    cid,
  )) {
    tags.set(t.id, [...(tags.get(t.id) ?? []), t.name].sort());
  }
  return all<Omit<SnapRow, 'tags'> & { id: number }>(
    `SELECT o.id AS id, o.comment AS comment, o.type AS type, o.paid_at AS paidAt, o.accrual_date AS accrualDate, a.name AS account, ta.name AS toAccount,
            o.to_amount AS toAmount, CASE WHEN o.type = 'transfer' THEN o.amount ELSE l.amount END AS amount,
            CASE WHEN o.type = 'transfer' THEN o.base_amount ELSE l.base_amount END AS baseAmount, cp.name AS counterparty,
            CASE WHEN pc.name IS NULL THEN c.name ELSE pc.name || ' → ' || c.name END AS category, p.name AS project
       FROM operations o
       JOIN accounts a ON a.id = o.account_id
       LEFT JOIN accounts ta ON ta.id = o.to_account_id
       LEFT JOIN counterparties cp ON cp.id = o.counterparty_id
       LEFT JOIN operation_lines l ON l.operation_id = o.id
       LEFT JOIN categories c ON c.id = l.category_id LEFT JOIN categories pc ON pc.id = c.parent_id
       LEFT JOIN projects p ON p.id = l.project_id
      WHERE o.company_id = ? AND o.deleted_at IS NULL`,
    cid,
  )
    .map(({ id, ...row }) => ({ ...row, tags: (tags.get(id) ?? []).join(',') }))
    .sort((a, b) => JSON.stringify(a).localeCompare(JSON.stringify(b)));
}

/**
 * Импорт готового файла .xlsx через API: загрузка, пересчёт с сопоставлениями (если заданы) и запись. Возвращает ответ
 * 201; любой другой ответ — исключение с телом. Так же импортируется выгрузка «Excel» (круг, §12 шаг 7).
 */
export async function importXlsx(w: OpsWorld, data: Buffer, opts: { accounts?: AccountMapping[]; name?: string; cid?: number } = {}): Promise<ImportCommitResult> {
  const base = `/api/v1/companies/${opts.cid ?? w.cid}/imports`;
  const up = await w.h.t.app.inject({
    method: 'POST',
    url: `${base}/upload`,
    headers: { ...ORIGIN_HEADERS, cookie: w.h.cookie, 'content-type': 'application/octet-stream', 'x-file-name': encodeURIComponent(opts.name ?? 'выгрузка.xlsx') },
    payload: data,
  });
  if (up.statusCode !== 200) throw new Error(`upload: ${up.statusCode} ${up.body}`);
  let p = up.json() as ImportPreview;
  if (opts.accounts) {
    const res = await w.h.req('POST', `${base}/preview`, { token: p.token, accounts: opts.accounts });
    if (res.statusCode !== 200) throw new Error(`preview: ${res.statusCode} ${res.body}`);
    p = res.json() as ImportPreview;
  }
  const res = await w.h.req('POST', base, { token: p.token, accounts: opts.accounts ?? [], revision: p.revision });
  if (res.statusCode !== 201) throw new Error(`commit: ${res.statusCode} ${res.body}`);
  return res.json() as ImportCommitResult;
}

## Экспорт и круг

Выгрузка берёт текущий период, фильтр и сортировку журнала, не больше 50 000 операций («Больше 50 000 операций — сузьте период или фильтр»). Имя файла — «{Компания} - Журнал - ДД-ММ-ГГГГ ЧЧ-ММ.xlsx» (время по `APP_TIMEZONE`; символы, запрещённые в Windows, заменены на «_»). Формул в файле нет: текст, начинающийся с `=`, `+`, `-`, `@`, табуляции или перевода строки, записан как текст.

1. **«Excel» — формат Finmap.**
   - 16 колонок в порядке шаблона импорта и его заголовки со звёздочками («Дата платежа*», «Сумма в валюте счета*», «Со счета*», «На счет*»); лист `ExportRU`; строка заголовков закреплена, итоговой строки нет.
   - Суммы положительные, тип операции следует из «Со счета» (расход), «На счет» (доход) или обеих колонок (перевод). «Сумма в валюте счета» — в валюте счёта списания, «Сумма в валюте компании» — в валюте компании.
   - **Разбитая операция** пишется строкой на каждую строку операции: сумма, категория и проект — свои, остальное повторяется. Загрузка такого файла создаст N отдельных операций: итоги по категориям и балансы счетов те же, число операций — по числу строк.
   - **Зарплата, налоги и НДС** с датой начисления, равной первому числу месяца, уходят периодом «с» — «по» («01.09.2026 00:00:00» — «30.09.2026 23:59:59»), «Дата начисления» при этом пуста; при загрузке период возвращается в ту же дату сделки. Остальные даты начисления — в «Дате начисления».
   - **Перевод между валютами:** в файле только сумма списания. Сумма зачисления при загрузке считается заново: в базовую валюту — из «Суммы в валюте компании», в другую — по нашим курсам на дату перевода. Если вы записали зачисление не по курсу (например, с комиссией банка), остаток счёта зачисления после круга отличается на эту разницу.
   - **Комментарий** пишется целиком. У нас он до 2 000 знаков, у Finmap — до 1 000: строку с более длинным комментарием Finmap не примет — сократите комментарий перед загрузкой в Finmap.
2. **«Собрать Excel».**
   - Одна строка на операцию; у разбитой категории, подкатегории и проекты строк — через «; ». Суммы со знаком: расход — минус, перевод — без знака. «Дата начисления» пишется всегда, период «с» и «по» — по тому же правилу, что в «Excel».
   - Последняя строка «Итого» (полужирным, значения — не формулы): сумма в валюте компании со знаком; «Сумма в валюте счета» и «Сумма зачисления» — только если у всех операций (переводов) одна валюта; подпись — в первой колонке без суммы. Переводы в сумму входят как есть, без знака.
   - Группа «Остатки и валюты» (наша): валюта счёта, остаток после операции, сумма, валюта и остаток зачисления.
   - Чтобы файл загружался обратно, оставьте «Дату платежа», «Сумму в валюте счета», «Со счета» и «На счет».
3. **Круг: выгрузка из клона — загрузка (§12 шаги 7–8).** Автоматически круг проверяют `npx vitest run tests/server/export-roundtrip.test.ts` (синтетическая компания с разбитыми операциями, периодом зарплаты и переводами между валютами и демо-набор). Вручную:
   - выгрузите «Экспортировать в» → «Excel» за всё время без фильтра;
   - создайте новую компанию с той же базовой валютой, без проектов;
   - в журнале нажмите «Импортировать», выберите файл; у каждого счёта — «Создать новый счёт», та же валюта, «Стартовый баланс» — как у счёта в исходной компании (настройки счетов) — так остатки проверяются, а не подгоняются;
   - после «Импортировать» остатки счетов в левой панели совпадают с исходными (у счетов, на которые зачислялись переводы между валютами не по курсу, — с поправкой на курсовую разницу), итоги по категориям тоже;
   - `npm run import:check -- <файл> <id новой компании>` — «Итог: Совпадает». Если в файле есть перевод в валюту, отличную от базовой, счёт-получатель помечен «?», итог — «Не сверено»: сравните его остаток с исходным вручную;
   - **Круг через Finmap:** 10–20 строк выгрузки «Excel» загрузите в тестовую компанию Finmap («Импорт из Excel») — импорт должен пройти без ошибок. Обратите внимание на заголовки со звёздочками, даты со временем и период зарплаты. Что проверить и записать — в `docs/superpowers/followups/2026-10-13-export-owner-checklist.md`.

- Открытые риски плана:
  - **Предел 50 000 операций при скачивании по ссылке:** сервер отвечает 422 JSON, браузер скачает его как файл ошибки (как и до плана Э); выгрузка по ссылке не показывает «Больше 50 000 операций…» на экране.
  - **Сумма зачисления перевода между валютами не по курсу** не переживает круг (§8.2, README); `import:check` такие счета не сверяет.
  - **Формат Finmap на вход:** принимает ли Finmap заголовки со звёздочками и период в колонках C/D, проверяется только вручную (§12 шаг 8, чек-лист).
  - **«Итого» в «Собрать Excel» включает переводы** с плюсом (буквально по §8.3); если владельцу нужен чистый итог — отдельное решение.
