# Учёт — финансы сети компьютерных клубов

Внутренний веб-инструмент управленческого учёта для юрлиц и их клубов (Казахстан, тенге). Функционал и UX повторяет Finmap, бренд собственный (`APP_NAME`).

- **Компания** — юрлицо.
- **Проект** — клуб, магазин или офис этого юрлица. Проект создаётся по шаблону типа бизнеса: «Компьютерный клуб» или «Общий».
- **Доступ:** «все видят всё», ролей нет.
- **Установка:** приложение поднимается одной командой на ПК клуба или на VPS. Снаружи оно доступно через Cloudflare Tunnel или ngrok.

Спецификация: [docs/superpowers/specs/2026-10-05-stage1-foundation-core-design.md](docs/superpowers/specs/2026-10-05-stage1-foundation-core-design.md).

## Что уже работает

Сделаны шаги 1–4 этапа 1 и серверная часть шага 5 (§11 спецификации):

- **Каркас:**
  - вход и выход, сессии с «запомнить меня»;
  - защита: CSRF, rate-limit, helmet;
  - история действий;
  - бэкапы и восстановление;
  - режимы запуска `local`, `cloudflare`, `ngrok`.
- **Компании и проекты:**
  - компании с системными статьями;
  - проекты по шаблонам;
  - переключатель компаний, который запоминает последнюю компанию.
- **Настройки:**
  - Проекты, Счета, Статьи (дерево, перетаскивание), Контрагенты, Теги, Шаблоны разделения, Курсы, Компании;
  - Пользователи, Профиль, История действий, Резервная копия.
- **Деньги (шаг 4):**
  - операции в API: доходы, расходы, переводы, разбиения по статьям и проектам, пересчёт в базовую валюту, удаление и восстановление;
  - вложения к операциям (png, jpg, webp, heic, pdf, xlsx, csv до 10 МБ) — пока только через API;
  - курсы: ручные на дату и фиксированные курсы компании (загрузка курсов Нацбанка отложена);
  - левая панель счетов с балансами и «Всего на счетах», итоги компаний в переключателе;
  - валюту счёта и базовую валюту компании нельзя сменить, если уже есть операции.
- **Журнал, сервер (шаг 5):**
  - список операций с фильтром, поиском без учёта регистра и «ё», сортировкой по дате и сумме и постраничной загрузкой;
  - остаток счёта после каждой операции;
  - массовые действия: статья, проект, контрагент, удаление и восстановление;
  - личные сохранённые фильтры;
  - выгрузка в Excel по текущему фильтру.

Пока нет (следующие шаги): экран журнала и форма операции, отчёты, мобильная версия и PWA.

## Требования

- Windows 10/11 x64 или Linux.
- Node.js 24 LTS. Build Tools не нужны: `better-sqlite3` и `@node-rs/argon2` ставятся готовыми бинарниками.
- Для внешнего доступа: аккаунт Cloudflare (туннель) или ngrok (authtoken и статический домен).

## Первый запуск

**Windows.** Из папки проекта:

```bat
setup.cmd
```

**Linux / macOS:**

```bash
./setup.sh
```

Обе команды делают одно и то же: `npm ci`, затем `npm run setup`. Скрипт `setup` спрашивает режим, адрес и порт, создаёт файл настроек `.env` с секретом сессии, применяет миграции и создаёт первого пользователя.

Если зависимости уже стоят, достаточно:

```bash
npm run setup
```

## Запуск

```bash
npm start
```

Команда:
- при необходимости собирает интерфейс;
- запускает сервер под супервизором, который перезапускает его при падении;
- в режиме `cloudflare` поднимает туннель, в режиме `ngrok` — подключение ngrok.

После запуска откройте адрес из консоли, по умолчанию http://127.0.0.1:3000. Остановка — `Ctrl+C`.

**Порт для одного запуска.** Порт можно задать переменной окружения, не трогая `.env`:

```bash
# Git Bash / Linux
PORT=3457 npm start
```

```powershell
# PowerShell
$env:PORT=3457; npm start
```

**Перед миграцией базы** создаётся бэкап, если база отстаёт от кода. Он лежит в `data/backups/backup-*.zip`.

**«Приложение уже запущено».** Если приложение не запущено, а эта ошибка появляется, удалите файл `data/app.lock`. Он остаётся после аварийного завершения.

### Показать приложение снаружи без настройки туннеля

Запустите приложение, затем во втором окне:

```bash
ngrok http 3457
```

Подставьте свой порт. ngrok выдаст временный https-адрес. Для постоянной работы используйте режимы `cloudflare` и `ngrok` (раздел «Режимы развёртывания»).

## Пользователи

| Команда | Что делает |
|---|---|
| `npm run user:add` | Добавить пользователя из консоли. Отвечать на вопросы нужно вручную: передача ответов через конвейер не работает. |
| `npm run user:passwd -- <логин>` | Сбросить пароль, если войти некому. Все сеансы пользователя завершаются. |

В интерфейсе: **Настройки → Пользователи** (добавить, сбросить пароль, отключить) и **Настройки → Профиль** (своё имя и пароль). Пароль — не короче 10 символов.

## Настройки (`.env`)

| Переменная | Значение по умолчанию | Смысл |
|---|---|---|
| `APP_NAME` | `Учёт` | Название в интерфейсе |
| `APP_TIMEZONE` | `Asia/Almaty` | Часовой пояс для дат |
| `HOST` | `127.0.0.1` | Адрес прослушивания. `0.0.0.0` — доступ из локальной сети по HTTP, без шифрования |
| `PORT` | `3000` | Порт |
| `PUBLIC_URL` | `http://localhost:PORT` | Внешний адрес, например `https://fin.example.kz` |
| `DEPLOY_MODE` | `local` | Режим: `local`, `cloudflare`, `ngrok` или `vps` |
| `CF_TUNNEL_TOKEN`, `CLOUDFLARED_PATH` | — | Для режима `cloudflare` |
| `NGROK_AUTHTOKEN`, `NGROK_DOMAIN` | — | Для режима `ngrok` |
| `SESSION_SECRET` | — | Генерирует `npm run setup`, не меньше 32 символов |
| `EXTRA_ORIGINS` | — | Дополнительные разрешённые адреса через запятую |
| `BACKUP_KEEP` | `14` | Сколько бэкапов хранить |
| `BACKUP_COPY_DIR` | — | Папка, куда копируется каждый бэкап: OneDrive, Google Drive, сетевая папка |

## Режимы развёртывания

- **`local`** — только на этом компьютере.
- **`cloudflare`** — постоянный https-адрес через Cloudflare Tunnel.
  - В панели Cloudflare создайте именованный туннель и укажите в нём адрес `http://127.0.0.1:PORT`.
  - Токен туннеля впишите в `CF_TUNNEL_TOKEN`, домен — в `PUBLIC_URL`.
  - `cloudflared` скачивается при `npm run setup`. Можно указать свой бинарник в `CLOUDFLARED_PATH`.
- **`ngrok`** — постоянный адрес на статическом домене ngrok. Нужны `NGROK_AUTHTOKEN` и `NGROK_DOMAIN`.
- **`vps`** — за обратным прокси, например Caddy. Подробная инструкция и автозапуск появятся на шаге 8.

## Данные и бэкапы

Всё хранится в папке `data/`:
- `app.db` — база SQLite;
- `uploads/` — вложения;
- `backups/` — архивы бэкапов;
- `logs/` — журналы.

Бэкапы:
- **Автоматически** — каждый день в 04:00 и при запуске, если последнему бэкапу больше суток. Хранятся последние `BACKUP_KEEP`.
- **Вручную** — командой `npm run backup` или в интерфейсе: **Настройки → Резервная копия → «Скачать сейчас»**.

Восстановление (сначала остановите приложение):

```bash
npm run restore -- data/backups/backup-20261006-040000.zip
```

Прежние данные сохраняются рядом, путь выводится в консоль. После восстановления все пользователи входят заново.

## Разработка

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер с перезапуском и Vite с горячей перезагрузкой |
| `npm test` | Юнит- и интеграционные тесты (Vitest) |
| `npm run typecheck` | Проверка типов |
| `npm run test:e2e` | E2E-тесты (Playwright). Порт задаётся `E2E_PORT`, по умолчанию 41731 |
| `npm run db:generate` | Сгенерировать миграцию после изменения `src/server/db/schema.ts` |
| `npm run seed:demo -- [число операций] [дата ГГГГ-ММ-ДД]` | Демо-набор (3 компании, 8 счетов, по умолчанию 10 000 операций за 2 года) — только в пустую базу и при остановленном приложении. Нужен пользователь (`npm run user:add`). Для отдельной демо-базы задайте `DATA_DIR` |
| `npm run bench:journal -- [папка]` | Замер скорости журнала на демо-наборе (§12): первая страница, фильтр и поиск должны отвечать на сервере быстрее 300 мс (p95). Набор заливается во временную папку один раз, около 45 с. Замер пишет только в свою папку (рядом с `app.db` лежит метка `bench-demo.marker`; чужую базу он не открывает на запись), весь замер идёт на одноразовой копии во временной папке, демо-копия между запусками не меняется |

Стек:
- сервер: Node 24, TypeScript, Fastify 5, SQLite (better-sqlite3), Drizzle ORM, zod;
- клиент: React 19, React Router, TanStack Query, Tailwind 4.

Структура:

```
src/server/   — API: модули по сущностям (modules/*), БД и миграции (db/), запуск (main.ts)
src/client/   — интерфейс: страницы (pages/), компоненты (components/), запросы (lib/)
src/shared/   — общий код: схемы zod, деньги, даты, валюты
src/templates/ — шаблоны типов бизнеса
scripts/      — setup, start (супервизор), user:add, user:passwd, backup, restore
tests/, e2e/  — тесты
docs/         — спецификация, планы, итоги этапов
```
