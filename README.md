# Учёт — финансы сети компьютерных клубов

Внутренний веб-инструмент управленческого учёта для юрлиц и их клубов (Казахстан, тенге). Функционал и UX повторяет Finmap, бренд собственный (`APP_NAME`).

- **Компания** — юрлицо.
- **Проект** — клуб, магазин или офис этого юрлица. Проект создаётся по шаблону типа бизнеса: «Компьютерный клуб» или «Общий».
- **Доступ:** «все видят всё», ролей нет.
- **Установка:** приложение поднимается одной командой на ПК клуба или на VPS. Снаружи оно доступно через Cloudflare Tunnel или ngrok.

Спецификация: [docs/superpowers/specs/2026-10-05-stage1-foundation-core-design.md](docs/superpowers/specs/2026-10-05-stage1-foundation-core-design.md).

  - журнал: тулбар в одну строку — меню периода («За предыдущий год», «Выбрать даты»), поиск, «Фильтр | ▾» с быстрыми фильтрами, «Ещё» (сумма, ⟳, колонки, выгрузка); дата в две строки, колонка «Дата сделки», «Показывать полностью»; «Указать» и «Изменить данные» — окнами; итог выделения по типам;

  - «Мои компании» карточками (архивные — отдельным блоком), «Пользователи» с «это вы» и «отключён», «Профиль» — одна форма с именем и сменой пароля; фиксированные и ручные курсы валют правятся в окнах; «Резервное копирование» — карточка «Автоматическая копия» (расписание, последняя копия, папка) и «Скачать сейчас»; ошибки показаны понятным языком.

- **Импорт из Finmap (планы И-2 и И-3):**
  - «Импортировать» в тулбаре журнала (на телефоне — «Ещё» → «Импорт из Excel») открывает панель «Импорт из Excel»: файл .xlsx или .csv в формате выгрузки Finmap «Excel» или шаблона («Скачать шаблон»), до 30 МБ и 50 000 строк;
  - проверка без записи: итог, ошибки по строкам, счета из файла с сопоставлением (новый счёт — «Текущий остаток» или «Стартовый баланс», существующий — «Остаток после импорта»), что будет создано, предупреждения, дубликаты;
  - «Импортировать» записывает всё одной транзакцией; если данные компании за время проверки изменились, панель показывает обновлённый итог;
  - сверка с файлом — `npm run import:check` (раздел «Импорт из Finmap»);
  - «История действий» → вкладка «Импорты»: кто, когда и какой файл импортировал; «Отменить» удаляет операции импорта, а созданные им счета и справочники — если они больше нигде не используются; операции, изменённые после импорта, по умолчанию остаются.

Пока нет (следующие шаги): экспорт в формате Finmap (план Э), отчёты.

## Требования

- Windows 10 версии 1903 или новее, или Windows 11 (автозапуск без окна использует `conhost --headless`), x64 (ПК клуба) или Linux-сервер (режим `vps`, например Ubuntu 24.04).
- Node.js 24 LTS — установщик с nodejs.org, все галочки по умолчанию. Visual Studio и Build Tools не нужны.
- Git — чтобы скачивать обновления (git-scm.com, настройки по умолчанию).
- Для доступа с телефона: свой домен в Cloudflare (режим `cloudflare`), бесплатный аккаунт ngrok (режим `ngrok`) или VPS (режим `vps`).

## Установка на ПК клуба (Windows)

1. Установите Node.js 24 LTS и Git.
2. Откройте свою папку пользователя: `Win+R`, введите `%USERPROFILE%`, Enter. Создайте в ней папку `Учёт` и откройте её. Не кладите проект прямо на диск `C:\`: там его файлы может читать любой пользователь компьютера, а в них пароли туннеля и база.
3. Щёлкните по адресной строке Проводника, наберите `cmd` и нажмите Enter — откроется окно команд в этой папке. В нём:
   ```bat
   git clone <адрес репозитория> finmap-clone
   cd finmap-clone
   setup.cmd
   ```
4. `setup.cmd` ставит зависимости и задаёт вопросы: режим (`local`, `cloudflare`, `ngrok` — см. «Режимы развёртывания»), адрес и токен, затем логин и пароль первого пользователя (не короче 10 символов). Он же закрывает папку `data` и файл настроек от других пользователей Windows.
5. Запустите приложение: `npm start`. Откройте адрес из окна (по умолчанию http://127.0.0.1:3000) и войдите. Это окно занято приложением — не закрывайте его.
6. Включите автозапуск в **новом** окне команд (снова `cmd` в адресной строке папки `finmap-clone`): `npm run service:install` (раздел «Автозапуск»).

**Linux / macOS вручную:** `./setup.sh`, затем `npm start`. Если зависимости уже стоят, достаточно `npm run setup`.

Дальше все команды выполняются в окне команд, открытом в папке проекта (`%USERPROFILE%\Учёт\finmap-clone`).

## Запуск и остановка

- **Запуск:** `npm start`. Команда собирает интерфейс (если нужно), запускает сервер под супервизором, который перезапускает его при падении, и в режимах `cloudflare` и `ngrok` поднимает туннель. Окно можно свернуть, но не закрывать — закрытие окна останавливает приложение.
- **Остановка:** `Ctrl+C` в окне приложения или `npm run stop` из любого окна в папке проекта. `npm run stop` нужен, когда приложение запущено автозапуском без окна. Он просит приложение завершиться штатно, а если оно не ответило за 20 секунд, завершает его принудительно. Он работает, даже если в настройках ошибка.
- **Журналы:** папка `data/logs`. В `supervisor.log` — запуски, остановки, перезапуски после падений, ошибки настроек и сборки, ошибки ngrok; в `cloudflared.log` — работа туннеля Cloudflare; в `app.*.log` — работа сервера.
- **Перед обновлением базы** (новая версия приложения) создаётся бэкап в `data/backups/`.

**Порт для одного запуска** можно задать переменной окружения, не трогая `.env`:

```bash
# Git Bash / Linux
PORT=3457 npm start
```

```powershell
# PowerShell
$env:PORT=3457; npm start
```

### Показать приложение снаружи без настройки туннеля

Запустите приложение, затем во втором окне `ngrok http 3457` (подставьте свой порт). ngrok выдаст временный https-адрес. Для постоянной работы используйте режимы `cloudflare` и `ngrok`.

## Пользователи

| Команда | Что делает |
|---|---|
| `npm run user:add` | Добавить пользователя из консоли. Отвечать на вопросы нужно вручную: передача ответов через конвейер не работает. |
| `npm run user:passwd -- <логин>` | Сбросить пароль, если войти некому. Все сеансы пользователя завершаются. |

На VPS все команды `npm run …` выполняйте от пользователя приложения: `sudo -u finmap -H npm run user:add`. Иначе файлы базы станут принадлежать root, и служба не сможет с ними работать.

В интерфейсе: **Настройки → Пользователи** (добавить, сбросить пароль, отключить) и **Настройки → Профиль** (своё имя и пароль). Пароль — не короче 10 символов.

## Настройки (`.env`)

Файл `.env` в папке проекта создаёт `npm run setup`. Чтобы изменить настройку:
1. Остановите приложение: `npm run stop` (на VPS — `sudo systemctl stop finmap-clone`).
2. Откройте `.env` Блокнотом, поправьте строку, сохраните (на VPS — в `/opt/finmap-clone/.env` от пользователя `finmap`, например `sudo -u finmap -H nano /opt/finmap-clone/.env`).
3. Запустите приложение: `npm start` или `schtasks /Run /TN finmap-clone` (на VPS — `sudo systemctl start finmap-clone`). Если в настройке ошибка, приложение не запустится, а причина будет в `data\logs\supervisor.log`.

| Переменная | Значение по умолчанию | Смысл |
|---|---|---|
| `APP_NAME` | `Учёт` | Название в интерфейсе и PWA |
| `APP_TIMEZONE` | `Asia/Almaty` | Часовой пояс для дат |
| `HOST` | `127.0.0.1` | Адрес прослушивания. `0.0.0.0` — доступ из локальной сети по HTTP, без шифрования |
| `PORT` | `3000` | Порт |
| `PUBLIC_URL` | `http://localhost:PORT` | Внешний адрес, например `https://fin.example.kz`. В режиме `vps` обязателен и начинается с `https://` |
| `DEPLOY_MODE` | `local` | Режим: `local`, `cloudflare`, `ngrok` или `vps` |
| `CF_TUNNEL_TOKEN`, `CLOUDFLARED_PATH` | — | Для режима `cloudflare` |
| `NGROK_AUTHTOKEN`, `NGROK_DOMAIN` | — | Для режима `ngrok` |
| `SESSION_SECRET` | — | Генерирует `npm run setup`, не меньше 32 символов |
| `EXTRA_ORIGINS` | — | Дополнительные разрешённые адреса через запятую |
| `BACKUP_KEEP` | `14` | Сколько бэкапов хранить |
| `BACKUP_COPY_DIR` | — | Существующая папка, куда копируется каждый бэкап: OneDrive, Google Drive, флешка, сетевая папка. Сама не создаётся; относительный путь отсчитывается от папки, из которой запущено приложение (обычно папка проекта) |

## Режимы развёртывания

### `local` — только этот компьютер

Приложение открывается по адресу http://127.0.0.1:3000 на самом ПК. С телефона недоступно.

### `cloudflare` — свой домен (рекомендуется для ПК клуба)

Нужен домен, подключённый к Cloudflare (бесплатный тариф подходит).

1. Войдите в панель Cloudflare → **Zero Trust** → **Networks** → **Tunnels** → **Create a tunnel** → тип **Cloudflared** → придумайте имя (например `club`).
2. На шаге установки Cloudflare показывает команду с длинным токеном после `--token`. Скопируйте только токен — сам `cloudflared` устанавливать не нужно, его скачивает `npm run setup`.
3. На шаге **Public Hostname** укажите поддомен (например `fin`), ваш домен, тип **HTTP** и адрес `127.0.0.1:3000`.
4. Запустите `npm run setup`, выберите `cloudflare`, введите адрес (`fin.example.kz`) и токен.
5. `npm start`. Адрес `https://fin.example.kz` открывается с телефона; в панели туннель должен стать **Healthy**.

Если `npm run setup` пишет, что закреплённой сборки `cloudflared` нет, скачайте `cloudflared-windows-amd64.exe` со страницы github.com/cloudflare/cloudflared/releases и укажите путь к файлу, когда setup спросит `CLOUDFLARED_PATH`.

### `ngrok` — постоянный адрес без своего домена

1. Зарегистрируйтесь на ngrok.com и подтвердите почту (без этого ngrok отвечает ошибкой `ERR_NGROK_4018`).
2. В панели ngrok: **Your Authtoken** — скопируйте токен; **Domains** — получите бесплатный статический домен вида `xxx.ngrok-free.app`.
3. `npm run setup` → `ngrok`, введите токен и домен. Затем `npm start`.

Ограничения бесплатного ngrok: при первом открытии сайта в каждом браузере показывается страница-предупреждение ngrok (нажмите **Visit Site**), действуют лимиты запросов и трафика. Если домен есть — выбирайте `cloudflare`.

### `vps` — свой сервер с Caddy

Пример для Ubuntu 24.04; домен `fin.example.kz` должен указывать на IP сервера (DNS-запись A).

1. Установите Node.js 24 (инструкция NodeSource на nodejs.org), Git и Caddy (инструкция для Ubuntu на caddyserver.com/docs/install).
2. Создайте пользователя приложения и папку:
   ```bash
   sudo adduser --system --group --home /home/finmap finmap
   sudo mkdir /opt/finmap-clone && sudo chown finmap:finmap /opt/finmap-clone
   sudo -u finmap -H git clone <адрес репозитория> /opt/finmap-clone
   cd /opt/finmap-clone
   sudo -u finmap -H ./setup.sh
   ```
   В `setup` выберите `vps` и введите домен. Позже `setup` на сервере тоже запускайте от пользователя приложения: `sudo -u finmap -H npm run setup`.
3. Подготовьте службу и Caddy: `sudo -u finmap -H npm run service:install`. Команда пишет `data/deploy/finmap-clone.service` и `data/deploy/Caddyfile` (образцы — в папке `deploy/`) и печатает команды. Выполните их:
   ```bash
   sudo cp '/opt/finmap-clone/data/deploy/finmap-clone.service' /etc/systemd/system/finmap-clone.service
   sudo systemctl daemon-reload
   sudo systemctl enable --now finmap-clone
   sudo cp --backup=numbered '/opt/finmap-clone/data/deploy/Caddyfile' /etc/caddy/Caddyfile
   sudo systemctl reload caddy
   ```
   Прежний `/etc/caddy/Caddyfile` при этом не теряется: он сохраняется рядом как `Caddyfile.~1~`. Если в Caddy уже есть другие сайты, не заменяйте `/etc/caddy/Caddyfile`, а добавьте в него блок из `data/deploy/Caddyfile`. Служба работает в песочнице: писать она может только в папку приложения, данные и папку копий бэкапов. Если вы поменяли `BACKUP_COPY_DIR` или `DATA_DIR`, повторите `service:install` и команды выше.
4. Откройте в брандмауэре порты 80 и 443 (`sudo ufw allow 80,443/tcp`). Порт приложения (3000) открывать не нужно: оно слушает только `127.0.0.1`, наружу его отдаёт Caddy.
5. Откройте `https://fin.example.kz`. Сертификат Caddy получает сам за минуту.

Управление: `sudo systemctl status|stop|start|restart finmap-clone`; журнал: `journalctl -u finmap-clone -f` и `data/logs`. На сервере останавливайте и запускайте приложение только через `systemctl`, не командами `npm run stop` и `npm start`: принудительно остановленную службу systemd поднимет заново. Все команды `npm run …` (`backup`, `restore`, `user:*`, `setup`) выполняйте от пользователя приложения: `sudo -u finmap -H npm run …`.

### На телефоне — как приложение

Откройте постоянный https-адрес (режимы `cloudflare`, `ngrok`, `vps`) и добавьте сайт на главный экран: в Safari на iPhone — «Поделиться» → «На экран „Домой“», в Chrome на Android — меню → «Установить приложение» (или «Добавить на главный экран»). Значок открывает приложение без адресной строки. Без сети приложение не работает (офлайн-режима нет). Временный адрес ngrok для этого не годится: после перезапуска он меняется, и значок перестаёт открываться.

## Автозапуск

### Windows

В новом окне команд в папке проекта (первое занято `npm start`):

```bat
npm run service:install
```

Команда создаёт задачу Планировщика `finmap-clone`. При входе вашего пользователя в Windows она запускает `npm start` без окна из папки проекта. Задача работает от имени того пользователя, который выполнил `service:install`, поэтому запускайте её под той учётной записью, под которой ПК клуба входит в Windows. При падении приложение перезапускает супервизор.

- Проверить без изменений: `npm run service:install -- --dry-run`.
- Запустить сейчас, не перезагружая ПК: сначала остановите ручной запуск (`Ctrl+C` в его окне), затем `schtasks /Run /TN finmap-clone`.
- Остановить: `npm run stop`. Выключить автозапуск: `npm run service:uninstall`, затем `npm run stop`. Если задачи нет, `service:uninstall` напишет «Задача автозапуска не найдена — удалять нечего.» и ничего не изменит.
- Если `schtasks` пишет «Отказано в доступе», откройте окно команд от имени администратора (Пуск → введите `cmd` → правой кнопкой «Запуск от имени администратора») **под своей учётной записью**. Такое окно открывается в папке `C:\Windows\System32`, поэтому сначала перейдите в папку проекта: `cd /d "%USERPROFILE%\Учёт\finmap-clone"`. Если Windows просит пароль **другого** администратора, не вводите его: задача создастся для того пользователя и при вашем входе не запустится. Попросите администратора дать вашей учётной записи права администратора и повторите.
- Если вы переустановили Node.js в другую папку, выполните `npm run service:install` ещё раз.
- Если на каком-то ПК всё же появилось чёрное окно, его можно свернуть, но не закрывать.

**Чтобы приложение поднималось после перезагрузки без человека**, включите автовход в Windows:
1. Нажмите `Win+R`, введите `netplwiz`, Enter.
2. Снимите галочку «Требовать ввод имени пользователя и пароля», нажмите «Применить» и введите пароль. Если галочки нет, в Windows 11 сначала выключите **Параметры → Учётные записи → Варианты входа → «Для повышения безопасности разрешить вход только с Windows Hello»**.
3. В **Параметрах → Система → Питание** поставьте «Переводить в спящий режим» — «Никогда»: спящий ПК недоступен с телефона.

Проверка: перезагрузите ПК, не трогая его. Через минуту-две адрес открывается с телефона.

### Linux

Systemd-служба из раздела «`vps` — свой сервер с Caddy» запускается при загрузке сервера. Выключить: `sudo -u finmap -H npm run service:uninstall` покажет команды.

## Данные и бэкапы

Всё хранится в папке `data/`:
- `app.db` — база SQLite;
- `uploads/` — вложения;
- `backups/` — архивы бэкапов;
- `logs/` — журналы.

Бэкапы:
- **Автоматически** — каждый день в 04:00 и при запуске, если последнему бэкапу больше суток. Хранятся последние `BACKUP_KEEP`.
- **Вручную** — командой `npm run backup` (на VPS — `sudo -u finmap -H npm run backup`) или в интерфейсе: **шестерёнка → Настройки компании → Резервное копирование → «Скачать сейчас»**.

### Копия бэкапов в другую папку (`BACKUP_COPY_DIR`)

Чтобы бэкапы пережили поломку диска ПК, копируйте их в облачную папку или на флешку:
1. Создайте папку, например `C:\Users\Админ\OneDrive\Учёт-бэкапы` или `E:\Бэкапы`.
2. Остановите приложение (`npm run stop`; на VPS — `sudo systemctl stop finmap-clone`), впишите в `.env` строку `BACKUP_COPY_DIR=C:\Users\Админ\OneDrive\Учёт-бэкапы` и запустите приложение снова (на VPS — `sudo systemctl start finmap-clone` после повторного `sudo -u finmap -H npm run service:install` и команд из раздела «vps»).

На Linux служба видит только те папки, которые существовали при её запуске. Если папку создали или смонтировали (флешку, сетевой диск) после старта службы, выполните `sudo systemctl restart finmap-clone`.

Лучше указывать полный путь: относительный путь отсчитывается от папки, из которой запущено приложение (обычно папка проекта). Каждый новый архив копируется в эту папку. В ней хранятся тоже последние `BACKUP_KEEP` архивов. Удаляются только файлы `backup-*.zip`, остальные файлы в папке не трогаются. Если папки нет (флешка отключена, диск не подключён), бэкап всё равно создаётся в `data/backups`. Тогда страница **Резервное копирование** (шестерёнка → Настройки компании) и журнал показывают ошибку копирования. Папка сама не создаётся, чтобы копия не попала на диск ПК вместо флешки. Для каждого ПК заведите отдельную папку.

## Восстановление из бэкапа

1. Остановите приложение: `npm run stop` (на VPS — `sudo systemctl stop finmap-clone`).
2. Восстановите архив (из `data/backups` или из папки копий):
   ```bash
   npm run restore -- data/backups/backup-20261006-040000.zip
   ```
   На VPS — от пользователя приложения, иначе файлы базы окажутся у root и служба не запустится:
   ```bash
   cd /opt/finmap-clone
   sudo -u finmap -H npm run restore -- data/backups/backup-20261006-040000.zip
   ```
3. Запустите приложение: `npm start` или `schtasks /Run /TN finmap-clone` (на VPS — `sudo systemctl start finmap-clone`).

Прежние данные сохраняются в `data/pre-restore-<время>/`, путь выводится в консоль. После восстановления все пользователи входят заново. Если архив сделан более новой версией приложения, сначала обновите приложение.

## Импорт из Finmap

Журнал из Finmap переносится файлом «Excel» — 16 колонок, тот же формат, что шаблон импорта Finmap. Подходит и файл, заполненный по нашему шаблону («Скачать шаблон» в панели импорта). Импортируйте в новую пустую компанию. Чтобы повторить импорт (например, с исправленным файлом), отмените прежний — «История действий» → «Импорты» → «Отменить импорт» (шаг 9) — и импортируйте снова в ту же компанию. Если ушли со страницы (кнопка «Назад» браузера) во время записи, импорт всё равно выполнится; повторная проверка того же файла покажет все строки дубликатами.

1. **В Finmap:**
   - запишите текущие остатки каждого счёта и «Всего на счетах»;
   - запишите стартовый баланс («Стартовый баланс» в настройках счёта) и дату открытия каждого счёта — по ним вы проверите импорт на шаге 5;
   - запишите итоги по категориям за всё время (Аналитика → по категориям) для доходов и расходов;
   - «Экспортировать в» → «Excel» за всё время, без фильтра.
2. **Файл с настоящими данными** держите вне репозитория: в папке `data/` или с именем вида `журнал.import-local.xlsx` — такие файлы git не видит.
3. **В клоне:**
   - создайте компанию, например «Клуб (проверка)», базовая валюта KZT, без проектов;
   - в журнале нажмите «Импортировать» (на телефоне — «Ещё» → «Импорт из Excel») и выберите файл.
4. **Проверка файла** ничего не записывает. Сверьте:
   - число операций и период — как в Finmap;
   - ошибок 0. Ошибки показаны с номерами строк Excel: исправьте файл и выберите его снова («Выбрать другой файл» — выбор счетов сохранится);
   - «Счета из файла»: для каждого счёта — «Создать новый счёт» или существующий счёт;
   - «Будет создано»: категории, контрагенты, проекты, теги. Число категорий будет меньше, чем в Finmap, на число системных категорий, которые уже есть в новой компании («Зарплата», «Налоги» и другие): они не создаются, а подхватываются. Это не ошибка. Если системные категории Finmap («Зарплата», «Налоги» и другие) попали в новые, сообщите разработчику их названия: они добавляются в `FINMAP_SYSTEM_ALIASES`.
5. **Остатки — главная проверка до записи.** У нового счёта оставьте «Текущий остаток» и введите остаток из Finmap: стартовый баланс посчитается сам, его значение видно под полем («Стартовый баланс: …»). Сравните его **до** «Импортировать» со стартовым балансом этого счёта в Finmap (шаг 1). Если значения разные, в файле не хватает строк или лишние (например, плановые операции) или сумма прочитана неверно: не импортируйте и сообщите разработчику. Именно эта проверка может не сойтись; равные текущие остатки после импорта её не заменяют (см. шаг 7). У существующего счёта есть необязательное «Остаток после импорта».
6. **«Импортировать»** записывает всё одной транзакцией: 16 000 строк — несколько секунд, панель в это время не закрывается. Итог — «Импорт завершён» с числом добавленных операций и созданных справочников.
   - «Данные компании изменились после проверки…» — компанию изменили за это время: посмотрите обновлённый итог и нажмите «Импортировать» ещё раз.
   - «Проверка устарела — файл проверен заново…» — сервер перезапускался или проверял другие файлы. Панель сама проверила файл заново: нажмите «Импортировать» ещё раз.
7. **Сверка:**
   - остатки счетов в левой панели и «Всего на счетах» совпадут с введёнными по построению: стартовый баланс подгоняется под них. Поэтому независимые проверки — стартовые балансы с шага 5, число операций и итоги по категориям из Finmap;
   - `npm run import:check -- <путь к файлу> <id компании> [--today ГГГГ-ММ-ДД]`; id компании — число в адресе журнала `/c/<id>/log`. Скрипт открывает базу только на чтение (приложение можно не останавливать), печатает «файл | база | разница» для числа операций, движения счетов и итогов по категориям и заканчивает строкой «Итог: Совпадает», «Итог: Расхождений: N» или «Итог: Не сверено: N» (строки с ошибками, неизвестным счётом или без суммы в валюте компании не сверяются и «Совпадает» не дают). Код выхода 0 — только при «Совпадает»;
   - скрипт сверяет базу с тем, как **этот же** разборщик читает файл: он ловит ошибки записи, но не ошибки чтения файла (для них — шаг 5 и итоги по категориям Finmap);
   - сверяется вся компания, а не только этот файл: поэтому нужна новая пустая компания, куда ничего не добавлено вручную;
   - плановые строки (дата платежа позже «сегодня») пропускаются, как при импорте. Если сверяете не в день импорта, укажите дату импорта: `--today ГГГГ-ММ-ДД`;
   - итоги по категориям из скрипта — как записанные в Finmap (только факт, без плановых);
   - несколько операций около полуночи (22:00–02:00) — та же дата и время, что в Finmap;
   - «Зарплата за {месяц}» — та же «Дата сделки».
8. **Повторный импорт того же файла** показывает все строки дубликатами, «Этот файл уже импортирован» и «Нечего импортировать: все строки — дубликаты».
9. **Отмена импорта:** значок «История действий» в шапке (на телефоне — «Ещё» → «История действий») → вкладка «Импорты» → «Отменить» у нужного файла → «Отменить импорт».
   - Удаляются все операции импорта, а также созданные им счета, категории, контрагенты, проекты и теги — если на них больше ничего не ссылается. Системные категории и всё, что было в компании до импорта, остаётся. У счетов, которые были до импорта, возвращаются прежние стартовый баланс и дата открытия — если их не меняли после импорта и не осталось операций раньше прежней даты открытия.
   - Операция, удалённая до отмены и датированная раньше восстановленной даты открытия счёта, восстанавливается только после того, как вы сдвинете дату открытия счёта назад.
   - Операции, которые после импорта правили или к которым прикрепили файл, по умолчанию остаются — подтверждение называет их число. Флажок «Удалить и изменённые» удаляет и их.
   - Что осталось и почему, видно в итоге: «Импорт отменён: удалено … Оставлено: …». Запись импорта остаётся в списке с пометкой «Отменён».
   - Счёт в архиве мешает отмене: верните его из архива и отмените снова.
   - После отмены журнал пуст (если в компании не было других операций): импортируйте файл снова с шага 3.

## Если что-то не работает

| Что случилось | Что сделать |
|---|---|
| «Приложение уже запущено» | `npm run stop` (на VPS — `sudo systemctl stop finmap-clone`) и повторите. Если не помогло и приложение точно не работает, удалите `data\app.lock` и `data\supervisor.lock` |
| После перезагрузки ПК не открывается | Проверьте, что Windows вошла в пользователя (автовход), и что задача есть: `schtasks /Query /TN finmap-clone`. Последние строки `data\logs\supervisor.log` подскажут причину |
| На ПК открывается, с телефона — нет | `cloudflare`: в панели Zero Trust туннель должен быть **Healthy**, подробности — в `data\logs\cloudflared.log`; `ngrok`: строки «Не удалось открыть туннель ngrok» в `supervisor.log` (`ERR_NGROK_4018` — подтвердите почту, `ERR_NGROK_105` — неверный токен). При такой ошибке туннель не поднимается повторно, а приложение продолжает работать на этом компьютере: исправьте настройки и перезапустите приложение |
| «Запрос отклонён защитой от подделки» | Сайт открыт по адресу, которого нет в `PUBLIC_URL` и `EXTRA_ORIGINS`. Откройте его по адресу из `PUBLIC_URL` или добавьте адрес в `EXTRA_ORIGINS` |
| VPS: сайт без HTTPS или ошибка сертификата | DNS-запись A указывает на сервер, порты 80 и 443 открыты; журнал Caddy: `journalctl -u caddy -f` |
| На «Резервное копирование» ошибка копирования | Подключите диск или создайте папку из `BACKUP_COPY_DIR`; следующий бэкап скопируется сам. На Linux, если папку создали или смонтировали после запуска службы, сначала выполните `sudo systemctl restart finmap-clone` |
| VPS: служба не стартует после `restore` или `backup`, в журнале `EACCES` | Команду запускали не от пользователя приложения. Выполните `sudo chown -R finmap:finmap /opt/finmap-clone/data` и запустите службу |
| `npm run stop` пишет «Не удалось остановить приложение даже принудительно» | Перезагрузите компьютер |
| `npm run stop` пишет «Не удалось остановить: файл блокировки в папке данных указывает на процесс, который не похож на приложение» | Убедитесь, что приложение не запущено (окно закрыто, в Диспетчере задач нет `node.exe` из папки проекта), перезагрузите компьютер и повторите. Файл блокировки остался от чужого процесса, `stop` его не трогает |
| В `supervisor.log` сервер постоянно перезапускается, в строках `[server]` есть `EADDRINUSE` | Порт занят чужой программой: поменяйте `PORT` в `.env` (и адрес туннеля в Cloudflare) |
| В `supervisor.log` строка «Порт N занят, а файл блокировки сервера остался от прошлого запуска; сервер будет запущен, когда порт освободится» | Нормально после перезагрузки или скачка часов: сервер запустится сам, когда порт освободится. Если строка повторяется несколько минут, проверьте, не занимает ли порт другая программа, или поменяйте `PORT` в `.env` (и адрес туннеля в Cloudflare) |
| Забыли пароль | `npm run user:passwd -- <логин>` |
| `npm run setup` пишет «база не тронута: приложение запущено» | Остановите приложение (`npm run stop`) и повторите `npm run setup`; настройки уже сохранены |
| `npm run setup` пишет «порт … занят другой программой» | Поменяйте `PORT` в `.env` (и адрес туннеля в Cloudflare) и повторите `npm run setup` |
| `npm run setup` пишет «не удалось закрыть … от других пользователей Windows» | Повторите `npm run setup` в окне команд, открытом от имени администратора под своей учётной записью |

## Разработка

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер с перезапуском и Vite с горячей перезагрузкой |
| `npm test` | Юнит- и интеграционные тесты (Vitest) |
| `npm run typecheck` | Проверка типов |
| `npm run test:e2e` | E2E-тесты (Playwright). Порт задаётся `E2E_PORT`, по умолчанию 41731 |
| `npm run db:generate` | Сгенерировать миграцию после изменения `src/server/db/schema.ts` |
| `npm run seed:demo -- [число операций] [дата ГГГГ-ММ-ДД]` | Демо-набор (3 компании, 8 счетов, по умолчанию 10 000 операций за 2 года) — только в пустую базу и при остановленном приложении. Нужен пользователь (`npm run user:add`). Для отдельной демо-базы задайте `DATA_DIR` |
| `npm run bench:journal -- [папка]` | Замер скорости журнала на демо-наборе (§12): первая страница, фильтр и поиск должны отвечать на сервере быстрее 300 мс (p95). Набор заливается во временную папку один раз, около 45 с. Замер пишет только в свою папку (рядом с `app.db` лежит метка `bench-demo.marker`; чужую базу он не открывает на запись), весь замер идёт на одноразовой копии во временной папке, демо-копия между запусками не меняется |
| `npm run import:check -- <файл> <id компании> [--today ГГГГ-ММ-ДД]` | Сверка импорта с файлом (§12 спецификации импорта): число операций, движение счетов и итоги по категориям — «файл \| база \| разница» и «Итог: Совпадает», «Итог: Расхождений: N» или «Итог: Не сверено: N». Сверяется вся компания. База открывается только на чтение; id компании — из адреса `/c/<id>/log`; `--today` — «сегодня» для плановых строк (по умолчанию — сегодня в `APP_TIMEZONE`) |
| `npm run bench:import` | Замер импорта (§10 спецификации импорта) на синтетическом файле во временной папке: загрузка, пересчёт, запись и отмена 16 000 строк (бюджеты 3 с, 1 с, 5 с и 3 с; пик памяти 16 000 строк — не больше 400 МБ), файл 50 000 строк (пик памяти не больше 500 МБ) и худший случай кэша проверки — три файла по 50 000 строк (пик памяти только измеряется, бюджета нет). Настоящие файлы не нужны, в CI не входит |
| `npm run shots:ux -- [папка]` | Визуальная сверка с Finmap (§12.3 этапа 1.5): поднимает свой сервер на временной базе с демо-набором (порт `SHOTS_PORT`, по умолчанию 41741), снимает наши экраны на 1440×900 и 390×844 под парными к снимкам Finmap именами и пишет `index.html` «Finmap \| наш». По умолчанию — в `docs/research/screens/v2/parity/` (в git не попадает) |

Стек:
- сервер: Node 24, TypeScript, Fastify 5, SQLite (better-sqlite3), Drizzle ORM, zod;
- клиент: React 19, React Router, TanStack Query, Tailwind 4.

Структура:

```
src/server/   — API: модули по сущностям (modules/*), БД и миграции (db/), запуск (main.ts)
src/client/   — интерфейс: страницы (pages/), компоненты (components/), запросы (lib/)
src/shared/   — общий код: схемы zod, деньги, даты, валюты
src/templates/ — шаблоны типов бизнеса
scripts/      — setup, start (супервизор), stop, service:install/uninstall, user:add, user:passwd, backup, restore
deploy/       — примеры Caddyfile и systemd-юнита для режима vps
tests/, e2e/  — тесты
docs/         — спецификация, планы, итоги этапов
```
